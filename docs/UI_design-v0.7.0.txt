《海战 OCEAN》UI 设计规范

版本：UI Design v0.7.0
开发基线：Ocean-project-postlaunch-v0.6.2
规则基线：rule-v1.4
Socket Protocol：1.5
适用版本：Ocean Game v0.7.x

一、版本定位

v0.7.x 专用于 UI、交互体验、视觉表现、响应式布局与可用性优化。

v0.7.x 不修改 v0.6.2 已有玩法逻辑，包括但不限于：
1. 不修改舰船数量、生命值、攻击范围、伤害、弹药数量和行动合法性。
2. 不修改 2 人 / 3 人模式的房间、回合、淘汰、胜负和最终齐射逻辑。
3. 不修改三人模式“每回合分别对两名仍在局敌人各完成一次操作”的规则。
4. 不修改三人模式两名敌人的独立敌方地图记录。
5. 不修改直升机在三人模式下同时作用于两名敌人的规则。
6. 不修改终局手动引爆诱饵鱼雷同时作用于其他所有仍在局敌人的规则。
7. 不修改首次雷达、瘫痪、超时、断线重连、投降和再来一局流程。
8. 不改变 Actor / Defender / Observer 的隐藏信息边界。
9. 不把后端权威判断转移到前端。
10. 不因 UI 便利新增自动攻击、自动选目标、自动跳过等规则外行为。

UI 的职责是让 v0.6.2 更易理解、更易操作、更易观察、更现代、更美观，而不是重新设计玩法。

二、核心设计原则

1. 现代应用交互
采用现代 Web 应用的信息架构和组件行为：
- 清晰的视觉层级
- 稳定布局
- 即时状态反馈
- 一致的按钮和表单状态
- Loading / Success / Error
- Toast / Modal / Tooltip
- 响应式布局
- 键盘焦点
- 减少动画支持

2. 少解释，多操作
主游戏页面不长期展示大段规则文字。
当前界面只展示：
- 现在是什么阶段
- 轮到谁
- 还有多少时间
- 当前需要做什么
- 当前可以做什么
- 操作结果是什么

完整说明统一放入：
- 游戏说明
- 新手教程
- 规则详情
- 帮助面板
- Tooltip
- 首次出现的一次性引导

3. 地图优先
地图是部署和对战阶段的核心交互区域。
任何装饰、战报、舰队列表、说明、动画都不能长期挤压或遮挡地图。

4. 信息不泄露
UI 只能显示当前客户端从服务器合法获得的信息。
不得通过颜色、动画、音效、格子状态、图标、HP 变化提示、Tooltip 或地图切换推测或泄露服务器未公开的信息。

三、视觉风格

定位：“现代海军战术终端 + 高质量现代 Web 应用”。

整体：
- 深海蓝 / 蓝黑背景
- 青蓝主交互色
- 绿色在线 / 成功
- 琥珀色等待 / 警告 / 即将超时
- 红色受击 / 危险 / 投降 / 失败
- 灰蓝色中性状态
- 克制的发光和半透明层次

避免：
- 复杂军用 HUD 边框
- 大量扫描线
- 高频闪烁
- 复杂粒子
- 全屏长动画
- 大片装饰性仪表盘
- 长期常驻规则说明

顶部栏：
- OCEAN 标志
- 房间号
- 2 人 / 3 人模式
- 当前连接状态
- 设置
- 帮助

主区域：

六、首页

目标：玩家进入后数秒内完成“创建房间”或“加入房间”。

推荐结构：

OCEAN
海战 · 战术对抗

[ 2 人对战 ] [ 3 人自由战 ]

[ 创建房间 ]

房间码
[ ________ ] [ 加入房间 ]

次要入口：
[ 游戏说明 ] [ 新手教程 ] [ 设置 ]

要求：
1. 创建房间是一级操作。
2. 加入房间清晰但不抢主按钮。
3. 2 人 / 3 人使用现代分段控件或模式卡片。
4. 首页不显示舰船数值表和长规则。
5. 非法房间码直接在输入区域反馈。
6. 手机端使用单列布局。

七、等待房间

使用统一玩家席位卡片。

2 人房：
P01
P02

3 人房：
P01
P02
P03

每个席位显示：
- 玩家编号 / 名称
- 在线状态
- 房主标识（如适用）
- 等待加入状态

顶部重点显示：
- 房间码
- 当前模式
- 当前人数

主要操作：
[ 复制邀请 ]
[ 离开房间 ]

房间未满时空席位显示“等待加入”。

不使用“双方”作为固定文案，统一使用“玩家”“其他玩家”“所有玩家”等多人兼容表达。

八、部署页

桌面端推荐：
左侧单位列表
中间己方 12×12 部署地图
右侧当前选择和操作

作战单位实例：
- 驱逐舰Ⅰ
- 驱逐舰Ⅱ
- 潜艇
- 核潜艇
- 海盗船
- 摩托艇 1
- 摩托艇 2
- 航空母舰

战术装置：
- 诱饵鱼雷 ×3

单位卡片只显示必要信息：
- 名称
- 是否已部署
- 当前方向 / 尺寸（有必要时）

主要操作：
[ 旋转 ]
[ 调整 ]
[ 随机部署 ]
[ 准备 ]

要求：
1. 合法部署预览清晰。
2. 非法部署明显但不过度警告。
3. 两艘摩托艇作为两个独立实例。
4. 已部署状态一眼可见。
5. 准备后显示锁定状态。
6. 不长期显示完整伤害规则。
7. 手机端可将单位列表改为底部 Sheet。

九、掷骰阶段

显示：
- 参与玩家
- 每名玩家骰点
- 当前等待状态
- 最终先手

骰子动画仅用于表现服务器返回结果，不改变任何逻辑或时序。

十、对战主界面

对战页是 v0.7.x 的最高优先级页面。

桌面端建议：

顶部：
- 当前玩家
- 回合顺序
- 90 秒倒计时
- 本回合完成进度
- 网络状态

主体：
- 己方地图
- 敌方地图区
- 己方舰队状态
- 行动面板

辅助区：
- 战况
- 私人情报
- 系统消息

十一、三人模式地图结构

v0.6.2 三人模式中，每名玩家拥有：
- 1 张己方地图
- 2 张互相独立的敌方地图

例如 A：
- A 己方地图
- B 敌方地图
- C 敌方地图

B 和 C 的攻击记录不得合并。

桌面大屏推荐默认同时展示三张地图：

[ A · 己方 ]
[ B · 敌方 ]
[ C · 敌方 ]

地图必须支持独立折叠 / 最小化。

每张地图左上角或标题栏提供：
[ − ] 最小化
[ □ ] 展开

最小化后保留紧凑地图标题卡，例如：

B · 敌方海域
本回合：已操作
[ 展开 ]

折叠行为只改变显示，不改变地图数据、当前目标、行动记录或服务器状态。

至少保留一张可操作地图处于展开状态。

十二、不同屏幕下的地图布局

宽屏：
三张地图可并排或“己方 + 两敌方”组合展示。

普通桌面：
己方地图可折叠为较小面板，两张敌方地图为主要区域。

较窄桌面 / 平板：
地图采用卡片切换：
[ 己方 ] [ P02 ] [ P03 ]
同时允许用户固定一张地图。

手机：
默认一次只显示一张地图，使用顶部 / 底部地图切换控件。

无论布局如何变化，B 与 C 的敌方地图仍是两套独立状态。

十三、三人模式回合进度

v0.6.2 中，A 的正常回合需要分别对 B、C 各完成一次操作。

UI 必须明确展示回合进度，例如：

A 的回合 · 01:12

对 B    ✓ 已完成
对 C    ● 待操作

第一项完成后：
- 不切换玩家
- 不重置 90 秒
- 明确提示仍需完成另一名敌人的操作

第二项完成后才进入下一玩家。

如果某名目标在回合过程中因既有规则出局，UI 根据服务器最新 remaining target 状态更新，不自行推断。

十四、三人模式操作自由组合

两名敌人的两次操作互相独立。

UI 不限制玩家必须使用相同行动。

例如合法 UI 流程可以是：
- 驱逐舰攻击 B
- 潜射导弹攻击 C

也可以：
- 震爆弹攻击 B
- 核弹攻击 C

或其他服务器允许的合法组合。

不得为了 UI 简化把三人回合改为“一次选择同时攻击两人”。

十五、目标地图与操作绑定

选择 B 地图时，当前普通单目标行动默认作用于 B。
选择 C 地图时，当前普通单目标行动默认作用于 C。

操作确认必须明确写出目标，例如：

驱逐舰Ⅰ冲撞
目标：P02
坐标：G7

[ 取消 ] [ 确认 ]

第一项完成后，对应敌方地图标题显示：
✓ 本回合已操作

最终合法性仍由服务器校验。

十六、直升机例外 UI

三人模式且两名敌人仍在局时：
直升机一次同时对 B、C 生效。

UI 必须把它显示为多目标行动，而不是普通单目标行动。

例如：

直升机扫射
目标：P02 + P03
区域：J 行

[ 取消 ] [ 确认扫射 ]

确认前，B、C 两张敌方地图可同时显示相同扫射范围预览。

执行后：
- 两张地图分别根据各自合法公开结果更新
- 只消耗一次直升机
- 当前整个回合结束

若当前只剩一名敌人，UI 按服务器状态展示为单目标直升机。

十七、首次雷达 UI

首次正常行动的强制雷达规则保持不变。

三人模式：
第一次操作使用雷达扫描一名敌人后，该回合仍需对另一名敌人完成第二项操作。

UI 推荐：

首次行动
雷达扫描

选择目标：
[ P02 ] [ P03 ]

完成后：

对 P02  ✓ 雷达已完成
对 P03  ● 待操作

随后恢复普通行动面板。

不得因为“首次雷达”视觉流程而提前结束整个三人回合。

十八、行动面板

现有动作：
- 驱逐舰Ⅰ冲撞
- 驱逐舰Ⅱ冲撞
- 海盗船攻击
- 摩托艇冲撞
- 潜射导弹
- 核弹
- 震爆弹
- 探测弹
- 航空母舰雷达扫描
- 直升机扫射

行动卡片显示：
- 图标
- 名称
- 剩余资源（适用时）
- 可用 / 不可用

不可用使用简短原因：
- 已耗尽
- 单位沉没
- 当前不可用
- 本回合不可执行

详细规则通过 Tooltip / 游戏说明查看。

十九、攻击范围交互

选择行动后，对应目标地图进入范围选择模式。

范围预览：
- valid
- invalid
- selected

矩形 / 行列 / 区域类行动使用轻量覆盖层。

不得在预览阶段暗示命中内容。

二十、地图 Cell State

统一地图格状态：

基础：
- unknown
- hover
- selectable
- selected
- invalid
- keyboard-focus

公开战斗：
- public-hit
- public-miss
- fired-unknown

私人：
- private-marker

范围：
- range-preview
- range-valid
- range-invalid
- radar-preview
- detection-preview

己方：
- own-unit
- damaged-unit
- sunk-unit
- paralyzed-unit
- decoy

要求：
1. fired-unknown 与 hit / miss 必须明显不同。
2. 潜射导弹、核弹等未知结果不得使用命中动画。
3. B/C 两张地图各自维护自己的 Cell State。
4. 地图折叠再展开后状态必须完整恢复。

二十一、己方舰队状态

舰队面板显示：
- 单位名称
- HP
- 当前状态
- 剩余特殊资源

示例：

驱逐舰Ⅰ
2.5 / 3
作战中

潜艇
2 / 2
潜射导弹 3

核潜艇
3 / 3
核弹 1 · 震爆 1 · 探测 0

状态：
- 正常
- 受伤
- 瘫痪
- 沉没

支持 0.5 HP 显示。

二十二、战况、私人情报与系统消息

建议拆成三个频道：

战况：
当前客户端允许看到的公共行动记录。

私人情报：
仅当前玩家可见，使用锁形图标 / 私人标签。

系统：
房间、回合、断线、重连、超时、淘汰、阶段切换。

三人公共记录明确“谁对谁”，例如：
P01 对 P03 使用驱逐舰Ⅰ冲撞，目标 G7，命中。

隐藏行动不得因 UI 增加额外信息。

二十三、命中与伤害反馈

命中：
短促命中效果 + 战况更新。

未命中：
较弱中性效果。

结果未知：
仅显示“已发射 / 已提交”类反馈。

自身受损：
己方舰队卡片短暂强调 HP 变化。

单位沉没：
一次性明确反馈，不做长时间遮挡。

二十四、瘫痪状态

瘫痪单位：
- 显示“瘫痪”
- 行动卡片对应禁用
- 使用状态图标

三人模式中，瘫痪状态按完整玩家回合处理。
UI 不在完成第一个敌方操作后自行解除，只根据服务器状态更新。

二十五、90 秒回合计时

三人两次操作共享同一个 90 秒回合。

第一项完成后，倒计时继续。

禁止：
- UI 重置为 90 秒
- 显示“新回合”
- 误导玩家认为第二项有额外时间

可以显示：

01:05
已完成 1 / 2

二十六、断线与重连

断线后按既有服务器逻辑显示：

P02 已断线
对局已暂停
重连剩余 01:43

自己正在恢复：
正在恢复对局…

恢复成功：
Toast：“已恢复对局”

地图折叠状态等纯 UI 偏好可本地保留。
游戏状态必须重新以服务器为准。

二十七、玩家淘汰

三人玩家淘汰后：
- 标记“已淘汰”
- 从待操作目标中移除
- 对应地图可继续查看既有合法历史记录
- 地图默认可折叠
- 回合顺序按服务器更新

不得主动删除此前合法可见的地图记录。

二十八、最终齐射 / 手动鱼雷

进入 FINAL_SALVO 后切换为独立阶段 UI。

三人模式中：
玩家选择一枚自己的尚未引爆诱饵鱼雷后，该坐标同时作用于其他所有仍在局敌人。

UI 例如：

最终齐射

选择己方诱饵鱼雷：
[ C4 ]
[ F8 ]
[ K2 ]

当前效果目标：
P02 + P03

[ 确认引爆 ]

不得让用户分别为 B、C 选择不同鱼雷，因为这会改变 v0.6.2 规则。

提交后：

已提交
等待其他玩家

P01  已提交
P02  等待
P03  已提交

不显示其他玩家秘密选择的鱼雷坐标。

二十九、结算页

展示：
- 胜利 / 失败 / 平局
- 各玩家最终状态
- 服务器允许公开的最终信息
- 复盘
- 再来一局
- 离开房间

三人“再来一局”分别显示每名玩家状态：

P01  已申请
P02  等待
P03  已申请

不退化成单一“对方已申请”。

三十、Toast / Modal / Tooltip

Toast：
- 复制成功
- 提交成功
- 重连成功
- 轻量错误

Modal：
仅用于高风险或不可逆确认：
- 投降
- 离开关键阶段
- 其他现有流程确实需要确认的操作

Tooltip：
用于短规则解释、图标含义、状态说明。

避免任何普通点击都弹 Modal。

三十一、游戏说明与教程

游戏说明集中展示完整规则。

至少包含：
- 2 人模式
- 3 人模式
- 三人每回合分别对两敌人操作
- 两张独立敌方地图
- 直升机多目标例外
- 最终鱼雷多目标例外
- 首次雷达
- 舰队
- 弹药
- 隐藏信息
- 最终齐射
- 断线重连
- 胜负

教程采用短步骤：
1. 创建 / 加入
2. 部署
3. 首次雷达
4. 选择地图和目标
5. 三人完成 1 / 2、2 / 2 操作
6. 查看战况
7. 地图折叠
8. 最终齐射

教程不在每局反复强制出现。

三十二、移动端设计

手机端不能简单缩小桌面布局。

推荐：

顶部：
当前玩家 / 倒计时 / 回合进度

地图切换：
[ 己方 ] [ P02 ] [ P03 ]

中间：
当前地图

底部固定操作区：
行动 / 参数 / 确认

抽屉：
舰队状态 / 战况 / 私人情报

要求：
1. 主要触控目标 ≥ 44 px。
2. 12×12 地图必须可准确点击。
3. 必要信息不能依赖 Hover。
4. 地图折叠 / 切换单手可操作。
5. 三人回合 1/2、2/2 进度始终可见。

三十七、测试要求

v0.6.2 既有 259 项逻辑测试必须继续全部通过。

UI 修改至少额外验证：
1. 2 人完整流程。
2. 3 人完整流程。
3. 三人每回合分别完成两名敌人的操作。
4. 第一项后不提前换人。
5. 第一项后 90 秒不重置。
6. B/C 敌方地图状态完全独立。
7. B/C 地图折叠和展开不丢状态。
8. 普通行动可在 B/C 使用不同组合。
9. 直升机同时对两名仍在局敌人显示和结算。
10. 直升机不被 UI 错误显示为需要分别执行两次。
11. 首次雷达后仍正确显示另一目标待操作。
12. 潜射导弹 / 核弹未知结果不泄露。
13. 探测和雷达私人信息不泄露。
14. 瘫痪状态直到完整玩家回合结束才按服务器更新。
15. 玩家中途淘汰后 remaining targets 正确更新。
16. FINAL_SALVO 一枚鱼雷同时作用于其他所有仍在局敌人。
17. UI 不允许在最终齐射中分别为 B/C 选择不同鱼雷。
18. 三人再来一局分别显示申请状态。
19. 手机端可完成三人整局。
20. 所有 UI 改动不得替代服务器权威判断。

三十八、最终验收标准

玩家进入首页：
能迅速创建或加入房间。

玩家进入等待：
能立即知道当前模式、房间号和等待谁。

玩家部署：
能明确知道当前单位、已部署单位和剩余内容。

玩家进入对战：
能立即知道：
- 当前轮到谁
- 还剩多少时间
- 本回合完成了几项
- 还需要对谁操作

三人模式：
能同时理解：
- 自己的地图
- B 的独立敌方地图
- C 的独立敌方地图
- 两张敌方地图的独立记录
- 哪张地图已经完成本回合操作
- 哪张地图仍待操作

地图空间不足：
可以最小化任意地图，而不是通过缩小所有地图牺牲可读性。

直升机：
明确显示为同时作用多个敌人。

最终鱼雷：
明确显示为一次选择同时作用其他所有仍在局敌人。

整个 UI：
- 不改变玩法
- 不泄露信息
- 不堆积注释
- 不用装饰阻碍地图
- 不让玩家重复猜测“现在该做什么”
- 保持现代、清晰、快速、稳定

让《海战 OCEAN》成为一款交互自然、信息清晰、视觉现代、适合 2 人和 3 人对战的完整 Web 海战游戏。
