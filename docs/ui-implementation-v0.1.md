# 《海战 OCEAN》正式页面实现设计 v0.1

> 实现目录：Ocean-project-ui-v0.1  
> 编制日期：2026-08-07  
> 唯一规则依据：rule-v1.0.md  
> 页面依据：page-flow-v1.0.md  
> 服务依据：Socket.IO 协议 1.2（继承 match-v0.5）  
> 边界：本文记录阶段 7 的代码实现，不改变冻结规则或页面流程。

## 1. 实现结论

本版本采用原生 HTML、CSS 和 JavaScript，把 P01～P06、O01～O05 实现为同一个 HTML 入口内的状态驱动界面。客户端不具有独立跳页权；收到每名玩家专属的 `room:state` 后，只按 `roomPhase` 选择页面。

运行时依赖仍只有 Express 与 Socket.IO。`jsdom` 只用于开发测试，不会下载到浏览器，也不参与正式运行。

## 2. 页面与覆盖层追踪

| 编号 | 实现内容 | 服务器驱动或本机状态 |
| --- | --- | --- |
| P01 | 昵称、创建、加入、6 位房间码、本机座位恢复 | 无房间快照；创建/加入/恢复应答 |

| P05 | 双地图、行动面板、目标确认、公开记录 | `PLAYING`；`FINAL_SALVO` 复用并锁定操作 |
| P06 | 结果摘要、完整复盘、再来一局、离开 | `FINISHED` |
| O01 | 精简规则、九项行动、图例、减少动画 | 本机 `<dialog>` |
| O02 | 离线玩家、120 秒倒计时、阶段对应操作 | 非 `CONNECTED` 的 `connectionPhase` |

## 3. 客户端模块

| 文件 | 职责 | 是否决定规则结果 |
| --- | --- | ---: |
| `game-data.js` | 正式名称、部署即时预检、随机部署、攻击范围与目标预览 | 否 |
| `ui-model.js` | 阶段映射、倒计时格式、行动禁用原因、公开记录文案 | 否 |
| `app.js` | Socket 会话、渲染、表单、部署编辑、目标确认、本机存储 | 否 |
| `main.css` | 状态视觉优先级、响应式布局、焦点与减少动画 | 否 |

浏览器预检可能提前阻止明显非法输入，但任何客户端检查都不能替代服务器校验。客户端只发送意图；服务器仍负责完整部署、目标合法性、命中、伤害、弹药、瘫痪、倒计时、回合切换、终局与胜负。

## 4. 舰队部署交互

### 4.1 对象模型

舰队清单固定为七个作战单位和三个独立 ID 的诱饵鱼雷。每项同时显示正式名称、形状、朝向和放置状态。

### 4.2 操作方式

- 直线单位：选择后点击起点，使用“旋转”或 R 键切换横向/纵向；
- 潜水艇、核潜艇：点击完整 2×2 的左上角；
- 摩托艇、诱饵鱼雷：点击一个目标格；
- 航空母舰：依次选择六个四向连通格；只允许撤销最后选择的一格；
- 已放置对象：桌面可拖动，手机可选中后点击新锚点；
- 已完成航空母舰：支持整体平移及顺时针旋转；
- 指针或键盘焦点经过候选起点时，以绿色/红色轮廓显示合法或非法预览；
- “撤销”保存最近 50 次本机编辑历史；
- “随机部署”和“清空部署”在覆盖已有内容前进入 O03。

“准备”按顺序发送完整 `deployment:submit`，等待相应状态版本，再发送 `deployment:ready`，避免用旧版本连续提交。准备后地图只读；服务器尚未锁定双方部署时可以取消准备。

## 5. 对战地图与信息隔离

### 5.1 己方地图

显示己方完整部署、生命值、弹药、受击格、残骸、诱饵状态和水下作战单位本回合瘫痪状态。选中驱逐舰行动时显示其来源轮廓及一个或两个中心格。

### 5.2 敌方地图

基础状态严格只有“未知、命中、未命中”。对局结束前不渲染敌方舰种、轮廓、沉没、生命值、弹药或诱饵身份。

显示优先级为：

1. 当前目标及范围预览；
2. 命中/未命中；
3. “导弹已发射”；
4. 私人标记 O；
5. 探测或震爆情报边框；
6. 海面底色。

“导弹已发射”不进入已结算集合，所以单格攻击仍可选择该格，范围攻击也不会跳过。私人标记只保存在本机，格子公开变为命中或未命中时自动删除。

## 6. 九项行动的页面实现

| 正式行动 | 页面选择 | 预览 | 确认与反馈约束 |
| --- | --- | --- | --- |
| 驱逐舰Ⅰ冲撞 | 单格 | 自身中间格为中心的 7×7，靠边裁切 | 提示命中才自损 1 |
| 驱逐舰Ⅱ冲撞 | 单格 | 中间两格几何中心的 8×8，靠边裁切 | 提示命中才自损 1 |
| 海盗船攻击 | 全图单格 | 所有未结算格 | 完整列出三类命中代价、未命中无伤害及特殊胜负 |
| 摩托艇冲撞 | 全图单格 | 所有未结算格 | 明确航空母舰、其他水面单位、水下单位和诱饵的不同结果 |
| 潜射导弹 | 全图单格 | 所有未结算格，含已有潜射标记格 | 发射方只见“导弹已发射”，明确不会取得结果 |
| 核弹 | 全图单格 | 所有未结算格 | 显示提交后剩余枚数 |
| 震爆弹 | 中心格 | C3～H8 的完整 5×5 | 明确只有水下作战单位可能瘫痪，施加方不知道结果 |
| 探测弹 | 中心格 | B2～I9 的完整 3×3 | 只显示布尔水下信号结果 |
| 直升机扫射 | 先选行/列，再点击坐标 | 完整十格；已结算格弱化并由服务器跳过 | 明确只命中水面单位、航空母舰总伤害上限 2 |

行动卡显示且区分：可用、等待回合、已沉没、瘫痪、弹药耗尽、尚未解锁、无合法目标和提交锁定。直升机的锁定文案固定为“己方两艘驱逐舰均沉没后解锁”。

目标选择后进入 O03；服务器接受前可以取消，接受后不可撤销。网络重试保留相同 `actionId`，状态版本冲突时主动同步最新安全快照。

## 7. 特殊行动反馈

- 潜射导弹：发射方只获得目标格和潜射标记；防守方只依据自己的安全反馈显示实际损伤；
- 震爆弹：施加方不显示成功、失败、数量、类型或坐标；防守方能看到自己的潜水艇或核潜艇实际瘫痪；
- 海盗船：攻击方正常看到海盗船和己方航空母舰的实际变化，但页面不直接公开敌方目标身份；
- 摩托艇：攻击确认明确“命中其他水面单位只显示命中但目标不扣生命值”；
- 直升机：攻击方只取得逐格命中/未命中，不取得目标类型；
- 探测弹：只显示“探测到水下信号”或“未探测到水下信号”。

所有显示只读取服务器已经裁剪的 `battle` 和 `latestResolution`；未结束时绝不接触 `replay`。

## 8. 断线、计时与恢复

- 服务器发送绝对截止时间，浏览器使用 `serverNow` 校准，不自行结束回合；
- 30 秒和 10 秒分别进入警告与紧急样式，不连续播放声音；
- 对局内有人离线时 O02 阻塞游戏操作，并显示该席位的服务器重连截止时间；
- 对局开始前提供“离开房间”；`PLAYING` 提供“投降并离开”；`FINAL_SALVO` 只等待服务器完成；
- “投降并离开”严格先等待 `match:surrender` 产生 `FINISHED`，再用新版本调用 `room:leave`；
- 本机连接中断时先锁定界面，Socket 恢复后使用轮换过的私密凭证重新取得完整安全快照；
- 客户端不会把私密凭证写入地址、DOM、日志或公开状态。

## 9. 响应式与可用性

- 桌面端同时显示己方与敌方地图；
- 1080 像素以下使用“敌方地图/己方地图”标签，默认敌方地图；
- 己方收到新反馈时标签显示提醒点；
- 900 像素以下行动面板成为可展开/收起的底部抽屉，公开记录也可折叠；
- A～J 与 1～10 坐标始终包含在地图结构中；
- 地图目标格为原生按钮，支持 Tab 聚焦和 Enter/Space 确认；
- 命中、未命中、潜射、瘫痪、禁用与警告均同时使用文字或图形；
- 支持系统 `prefers-reduced-motion`，也可在 O01 单独保存“减少动画”偏好。

## 10. 本机存储边界

| 键 | 内容 | 是否发送给对手 |
| --- | --- | ---: |
| `ocean.reconnect-session.v1` | 房间码与私密重连凭证 | 否；只发给服务器恢复接口 |
| `ocean.private-markers.v1:*` | 当前设备的敌方地图 O 标记 | 否 |
| `ocean.reduce-motion.v1` | 减少动画偏好 | 否 |

新一局进入 `DEPLOYING` 时清除上局私人标记；同一局刷新或重连时恢复。
