## 0. 使用方式、继承关系与责任

本次用户明确要求“增加更多动态特效”。目标是在已完成的 UI 结构上增加辨识度、过程感和反馈质量，保留清晰、稳定、易操作的控制台。开发不得重新退回旧版驾驶舱布局，也不以增加装饰数量作为完成标准。

本文是 v1.4 增量规范。页面布局、规则、十种行动、权限、确认流程、三主题五强调色、键盘操作和原有功能继续继承 v1.3；无需重复实现。本文明确收紧或细化的动效数值优先于 v1.3 第20节；未明确替代的旧性能、布局、隐私和可访问性要求继续生效。两份规范不能互相抵消硬性要求。

## 1. 目标、范围与完成定义

设计主张：**让玩家感受到“选择—准备—执行—落点—回响”，同时能在任何一帧看清并操作当前局面。**

“更多”具体指覆盖更多真实状态、使不同武器的运动语言不同、补足关键事件前后的连续反馈。核弹、雷达、冲撞不能只是换一张图片播放同一种缩放；等待页面也不需要为填满屏幕不停发光。

本轮包含：海图环境、全局微交互、部署反馈、掷骰与回合交接、十种行动、己方受击/瘫痪/沉没、最终齐射、胜负、教程和设置中的动态降级。既有音效只作同步与防重整合，不要求新增音源。

| 编号 | 必须要求与通过条件 |
| --- | --- |
| MV-SCP-01 | 完成本文页面清单、十行动清单、事件生命周期、画质/减少动画、异常恢复与证据交付；不能只实现首页背景或一两种攻击就称为整轮完成。 |
| MV-SCP-02 | 不新增舰艇移动、炮弹飞行规则、武器、地图尺寸、三人人机、观战、战报联网或其他产品玩法；视觉过程不参与命中、扣血、耗弹和胜负计算。 |
| MV-SCP-03 | 选择目标只更新草稿；确认执行依然是唯一业务提交入口。hover、动效预览、粒子、动画结束、切图和重播不能发送 action:submit/final-salvo:submit。 |
| MV-SCP-04 | 所有控制台、主操作和文字布局沿用现有 UI；不重新增加金属边框、常驻雷达盘、伪仪表、随机日志和假信号来制造科技感。 |
| MV-SCP-05 | 高画质下十种行动各有独立编排定义，并能从方向、范围、时序或形态中的至少两项辨认差异；共享爆炸收尾可以复用，单纯换色/换贴图不算完整实现。 |
| MV-SCP-06 | 关闭动画后，当前阶段、合法范围、目标、成本/风险、结果文字、永久事实标记和所有操作仍完整可用；任何必要信息不只存在于运动过程中。 |

## 2. 视觉纪律：增加动感，控制噪声

动效分四层：环境提供空间感；交互确认输入；过程表达已确认行动；结果强调已知变化。事实层、坐标层和可操作区域始终有最高可读优先级。

| 编号 | 必须要求与通过条件 |
| --- | --- |
| MV-VIS-01 | 普通表单、舰队卡、日志、计时、按钮区域不循环装饰动画。真实待提交/连接请求可有一处必要进度指示；它必须随请求结束停止，不能用假进度表示真实百分比。 |
| MV-VIS-02 | 当前可见海图最多一层主要持续环境动画；海面高光、焦散、薄雾中只选一种运动，其他作为静态材质。不同时叠加流动网格、粒子雨和旋转雷达。 |
| MV-VIS-03 | 同时最多一个主要战斗过程效果。次级舰队HP条反馈、结果标签和短交互提示可并存，但不能重复播放同一场爆炸或把所有面板同步点亮。 |
| MV-VIS-04 | 海图环境层整体合成不透明度上限：暗/暮色0.12，浅色0.08；事件核心以局部透明纹理表现，不能用大面积纯色盖住目标坐标、格线、事实符号。 |
| MV-VIS-05 | 动态环境不得模拟情报：不能随机冒出接触点、舰体轮廓、目标航迹、未知数量或敌方信号。环境在不同秘密部署下应具有相同分布和生成规则。 |
| MV-VIS-06 | 不移动、旋转、透视或缩放真实地图、船体位置、点击格与整页视口来表现冲击；允许仅装饰层在原锚点内≤2px位移，减少动画时为0。 |
| MV-VIS-07 | 不使用整屏闪白、反复高对比闪烁、全局模糊、色差抖动或高饱和爆光。全画面任意区域均不得出现每秒超过3次的高对比闪烁；核弹只允许一次柔和局部亮起。 |
| MV-VIS-08 | 活跃事件结束后，500ms内回到静态工作态，仅保留原本允许的单一海图环境循环和事实标记；不留下持续火焰、永久电弧、低血量闪红框。 |
| MV-VIS-09 | 目标/焦点/非法范围、原有命中与私人标记在整个效果期间均可识别。装饰层不能制造与事实相同的实心符号，不能降低必要文字、边界和状态的原对比度要求。 |
| MV-VIS-10 | 三主题、五强调色均保留语义色区分；改变用户强调色不把命中、未知、瘫痪和私人侦察全部染成同色。浅色主题采用更深的核心边线，避免白色光晕隐失。 |

## 3. 统一时间、强度与运动令牌

以下时间是视觉效果开始后的本地相对时间，不含网络等待。S0为本地交互被接受；E0为去重后、当前会话首次接受的新服务器事件；H0为服务器确认结果被应用到界面。事实和业务状态必须在H0按现有逻辑立即更新，装饰时间线不延迟事实。

同一动作结果反馈已到达时，不再为了等动画让HP或结果文字暂时显示旧值。对事件时间线的“发射—落点”是已确认事件的视觉解释，不是服务器仍在计算的承诺。

| 令牌/用途 | 高画质 | 流畅 | 减少动画 |
| --- | --- | --- | --- |
| control / hover、按压、radio | 100–160ms；图标≤1px，按钮点击框不动 | 80–120ms，仅颜色/透明度 | 直接切换；允许≤80ms颜色/透明度 |
| lock / 目标锁定 | 180–240ms，一次准线从外扩4px内收 | ≤120ms边界淡入 | 静态高亮 |
| panel / 抽屉、对话框 | 180–220ms；内容装饰≤16px单轴 | ≤140ms；≤8px | 直接显示 |
| page / 页面、分区进入 | 160–220ms；最多一次整体淡入 | ≤120ms | 直接显示 |
| deploy / 放置、合法旋转 | 140–220ms；仅边界确认 | ≤120ms | 静态合法/非法状态 |
| layer / 水面潜层切换 | 320–520ms，一次柔和扫过 | ≤120ms透明度交接 | 直接切换 |
| ambient / 海面环境 | 12–20秒一个周期；位移≤8px | 停止 | 停止 |
| turn / 回合归属 | 240–400ms一次侧边/下划线提示 | ≤160ms | 文字与静态形状立即更新 |
| hp / 已知HP减少 | 数字立即更新，条带余影200–400ms | ≤160ms | 数字与条带立即更新 |
| combat / 通常战斗 | 每行动700–1400ms，见第6节 | 180–360ms | 不播放空间运动，直接事实反馈 |
| salvo / 齐射一轮 | 900–1400ms | ≤360ms | 静态轮次与结果 |
| result / 胜负 | 700–1100ms一次局部徽记 | ≤240ms | 静态结果 |

默认缓出曲线可采用 cubic-bezier(0.22,1,0.36,1)，线性仅用于扫描、轨迹和旋转。禁止回弹/弹簧导致目标边界越界、正文晃动。

| 编号 | 必须要求与通过条件 |
| --- | --- |
| MV-TIM-01 | 统一令牌进入样式或配置表，禁止十行动各自散落无来源的魔法时长。表内时长允许一次明确范围内的取值，不要求随机变化。 |
| MV-TIM-02 | 所有已确认战斗事件的运动在E0后1800ms内完成，装饰DOM/动画句柄在2000ms内释放；显著收紧旧版≤3600ms的上限。持久事实不随效果销毁。 |
| MV-TIM-03 | 本地选点、切图、展开与取消应立即有反馈；任何动画都不能额外锁住合法业务操作。不能await动画完成后才发送请求或应用服务器回合/截止时间。 |
| MV-TIM-04 | 元素序列进入最多3组，每组错开≤40ms，总视觉进入≤300ms；禁止225个格子逐格出场。页面进入首帧即有可操作内容，退出动画不延迟新页面。 |
| MV-TIM-05 | 同一事件内按绝对时间点或单一受控时间线编排，避免多层setTimeout漂移。页面切换、用户偏好变化、后台与新事件都能统一取消。 |

## 5. 战场环境与空间锚定

环境让海图有生命感，不能给格子添加不确定性。舰体与诱饵在已锁定坐标中保持静止，波纹运动只发生在独立装饰层。海面不需要3D引擎。

| 编号 | 必须要求与通过条件 |
| --- | --- |
| MV-ENV-01 | 高画质在当前可见战斗海图提供一层12–20秒周期、≤8px位移的高光或焦散缓变；流畅/减少动画/后台均停止。默认海图基底与格线静止，常态无粒子雨。 |
| MV-ENV-02 | 海图切水面与潜层时，变化局限于环境颜色/选定扫描纹理；己方实际舰体位置、可见性规则、格子、坐标和输入保持不变。不把显示层切换表现成真实船只上浮/下潜。 |
| MV-ENV-03 | 单格、区域与整行列效果按当前格子矩形映射，包含轴宽和实际滚动偏移；容器负责裁切。390px手机平移后不得把落点留在屏幕旧坐标。 |

## 6. 十种行动的动态编排

### 6.1 共同规则

表内时间从E0计。常规编排分“起势—过程—收束”，但相应文字、HP与永久地图事实在服务器事件被应用时已经就位。起势不是预提交预测。

区域扫描的装饰可以覆盖已授权的扫描区；不能把扫描区中的真舰格当作粒子出生点。攻击方若只知道命中/未命中，收束只能针对该事实，不追加舰种、HP、残骸、数量或整舰沉没。

## 8. 隐私与结果保密：视觉也是输出

特效纹理、声音、时间、颗粒数量、位置、数据属性和加载资源都可能泄露信息。所有可见差异只能来自接收者合法可见的事实。

| 角色/行动 | 可以表现 | 禁止额外输出 |
| --- | --- | --- |
| 攻击方：常规冲撞/海盗/摩托艇 | 目标与安全hit/miss、自己已知自损 | 被击舰种、HP、整舰长度、诱饵身份、隐藏沉没 |
| 攻击方：导弹/核弹/震爆 | 已执行过程、中性范围、结果保密 | 命中/落空差异、爆炸类型差异、瘫痪成功、碎片数量差异 |
| 攻击方：雷达/探测 | 合法区域级布尔反馈 | 精确舰格、数量、舰种、轮廓、命中声 |
| 防守方：自己受击 | 自己合法快照与receivedHits/ownDamage对应变化 | 对手其他目标的私人侦察结果、对手秘密来源坐标 |
| 三人未受影响/未获私人结果者 | 自己收到的公开行动事实 | 另一方私有结果、整舰状态 |
| 结算复盘 | FINISHED且已有合法replay提供的信息 | 从未到达的未来记录或对局尚未结束时提前取replay |

| 编号 | 必须要求与通过条件 |
| --- | --- |
| MV-SEC-01 | 动效模型仅接受显式安全字段组成的提示对象，不持有room全量、服务端outcome原始对象或敌方完整快照。不可用CSS隐藏非法信息，非法数据不得进入DOM/Canvas/日志。 |
| MV-SEC-02 | 对隐藏世界不同但该接收者安全输入完全相同的两份样例，效果描述、资源列表、时间线、数据属性、音效调用均相同；装饰随机需固定种子或独立于秘密数据，不能按hiddenHit生成。 |
| MV-SEC-03 | 导弹/核弹/震爆攻击方的提示kind固定为neutral/unknown；即使内部测试夹具附带“实际命中”，也不能进入爆炸/水花/瘫痪分支。测试必须覆盖真假配对。 |
| MV-SEC-04 | 雷达/探测positive与negative允许区域级形态/标签不同；同为positive的不同秘密舰位必须产生相同效果，不能返回“信号中心”或强弱数量。 |

| MV-SEC-06 | 本轮不要求新增服务端Socket事件或扩大安全投影。现有数据不足以安全表现的细节使用中性回退，而不是向客户端额外广播。 |

## 9. 事件生命周期、去重与取消

### 9.1 数据与状态流程

    已校验的安全room view / 有效本地交互
      → 识别接收身份、房间、对局与新鲜事件
      → 构造最小安全提示 MotionCue
      → 画质/减少动画/前后台/可见地图裁决
      → 取消上一主效果，渲染新效果或静态回退
      → 超时/完成/切页统一释放

建议 MotionCue 最小字段如下；名称可以调整，含义必须保留。不要为适配此结构引入新的网络协议。

| 字段 | 内容/边界 |
| --- | --- |
| key | 接收身份 + roomCode + matchSummary.startedAt或等效对局键 + sequence/事件种类；不得用每次stateVersion变化当作新动作 |
| kind | 本地交互、回合、行动、己方状态、齐射、结果之一 |
| actionType | 十行动之一；本地装饰可为空 |
| mapId | own或当前安全敌方playerId；不能用敌方数组下标作持久身份 |
| safeTarget | 已授权coordinate/区域/行列与Data算出的合法格，禁止额外精确舰格 |
| result | 当前接收者合法的hit/miss/unknown/区域positive-negative；不能包含隐藏actualResult |
| ownChanges | 经同身份、同局previous/next安全own快照差分得到的己方事实，按unitId |
| freshness | 新接收事件、恢复快照或历史之一；恢复/历史默认静态 |
| createdAt / expiresAt | 本地单调时钟，最迟E0后2000ms清除，后台期间仍过期 |
| seed | 可选，仅由安全cue key派生；不使用秘密舰位、HP、命中结果或token |

不建议逐帧修改state或调用整个render()；已有render会重建内容，因此效果调度应在提交/渲染之后稳定挂载，并保证无关render不会重新开始动画。可采用专用图层、受控Animation句柄或局部patch。无需为了这一轮迁移整个框架。

| 编号 | 必须要求与通过条件 |
| --- | --- |
| MV-LIFE-01 | 本地草稿仅能触发选择/锁定提示。战斗过程只由已确认的新鲜安全事件触发；仅action:submit已发送或ACK无结果，不构成命中/发射成功证据。 |

## 10. 画质、减少动画与可访问性

不新增“电影模式”“特效强度”第四套设置。沿用自动/高画质/流畅与减少动画，降低用户决策成本。暂停非必要连续动画的可见入口为已有减少动画开关；可从帮助/个性化设置到达。

| 效果 | 高画质 | 流畅 | 减少动画/强制颜色 |
| --- | --- | --- | --- |
| 海面持续层 | 一层缓慢高光或焦散 | 静态 | 停止并保留清晰底图 |
| 目标选择 | 一次准线收敛 | 短边界淡入 | 静态高亮 |
| 攻击 | 主形态+必要辅助纹理，局部粒子受限 | 单形态、无粒子/模糊/多阴影 | 无空间运动，结果文字/事实立即更新 |
| 状态变化 | 局部短效+条带余影 | 短线条提示 | 静态图标与数值 |
| 抽屉/页面 | 短时淡入与轻位移 | 更短透明度交接 | 直接显示 |
| 掷骰等待 | 一次短旋转后静态等待 | 短透明度切换 | 静态“等待服务器结果” |
| 胜负 | 一次局部徽记完成 | 短淡入 | 静态标题 |
| 音效 | 沿用独立效果开关 | 同一信息量，沿用音量 | 减少动画不替用户改变音效偏好；仍受独立静音控制 |

| 编号 | 必须要求与通过条件 |
| --- | --- |
| MV-ACC-01 | 有效减少动画=用户明确开启或系统prefers-reduced-motion启用；系统改变即时生效，不把系统值永久写成用户偏好。高画质手动选择不得覆盖减少动画。 |
| MV-ACC-02 | 开启减少动画时当帧停止环境和未完成空间运动，直接展示当前事实；≤100ms完成清理。关闭后不补播旧事件，仅未来事件采用新策略。 |
| MV-ACC-03 | 流畅关闭粒子、持续环境、运动模糊和大面积动态滤镜；仍保留十行动的明确名称、目标、公开结果、焦点与交互。流畅不等于功能缩水。 |
| MV-ACC-04 | 自动初始策略继承现有小视口/内存/核心数判断。缺少这些浏览器字段不能报错。仅自动高画质且可见、正在播放实际动画时采样；热身后连续两个3秒有效窗口平均帧间隔>35ms时降为流畅，并显示“自动·当前流畅”。静止、流畅与减少动画不为监测单独维持rAF。 |
| MV-ACC-05 | 动态降级只在auto中改变有效画质，不覆写用户保存的auto，也不在同局自动升降振荡。手动high/smooth保持选择，减少动画仍优先；页面hidden和开发工具暂停时间不参与性能降级样本。 |
| MV-ACC-06 | 新效果图形全部aria-hidden、无tabindex；读屏只播报事件事实一次，不播报“光环开始/扫描第几帧”。被镜像隐藏的Toast不可重新变为遮挡浮层。 |
| MV-ACC-07 | 关键状态不能只靠颜色、音效或运动方向。200%缩放、键盘、高对比/forced-colors下仍能识别目标与操作；装饰在forced-colors下可全部隐藏。 |
| MV-ACC-08 | 持续动画不抢焦点；抽屉进出仍保持原焦点圈定与返回；地图格roving tabindex、Enter/Space选点和删除私人标记保持原行为。 |

## 11. 音画协作

本轮以视觉为主，不新加音源，不改变音乐选择/音量体系。需要整理的是“一件事只被播一次”和隐藏结果的等价表现。

| 编号 | 必须要求与通过条件 |
| --- | --- |
| MV-SND-01 | 声音继续由既有Sound接口和独立开关控制；主效果调度与原acceptRoomState音效触发只选一处作为同一事件的所有者，不两边各播一次。 |
| MV-SND-02 | 同一次三人行动只播放一次主动作音；同事件的重复快照、切图、恢复和本地演示不能泄漏或叠加真实对局音效。 |
| MV-SND-03 | 导弹/核弹/震爆攻击方使用固定中性音；雷达/探测根据允许布尔结果，不能按隐藏命中数量/单位改变音高、音量、声道或时长。 |
| MV-SND-04 | 已有动作音与效果主节点同步，资源预热后的目标偏差≤120ms；若音频未解锁/未就绪则省略该次，不延迟业务、不补播陈旧声音。 |
| MV-SND-05 | 关闭音效立即停止本轮新增的延迟/循环播放句柄。场景销毁后不得响起旧攻击声；音乐音量与播放状态保持原独立行为。最大效果音并发仍≤12。 |
| MV-SND-06 | 减少动画不要求关闭已授权的短动作音，也不允许以声音作为被移除视觉的唯一替代；事件文字与静态事实始终存在。 |

## 12. 性能、资源与移动端预算

以下是新验收要求，不是当前性能已达标的陈述。正式采样沿用v1.3第23节：固定机器/浏览器版本、1366×768与1920×1080桌面、390×844及4倍CPU模拟、真实手机、15×15三人安全快照与100条日志。每种交互预热一次后至少30次样本；加载至少5次冷缓存。真实设备不足要记录未测。

| 编号 | 必须要求与通过条件 |
| --- | --- |
| MV-PERF-01 | 继续达到v1.3 PERF-01～10：本地反馈p95桌面≤100ms/4倍CPU≤200ms，切图/展开稳定≤200/350ms；新增特效不得把网络等待混入客户端耗时掩盖卡顿。 |
| MV-PERF-02 | 桌面高画质连续10秒动效平均≥45fps，桌面流畅≥55fps，4倍CPU手机模拟流畅≥30fps；实际低刷新率设备单独报告，不能冒充符合60Hz参考条件。 |
| MV-PERF-03 | 新增效果引入的单次主线程任务≤50ms；静态待命不得出现由特效造成的>200ms长任务。每帧不得对225个格子逐个读布局再写样式。 |
| MV-PERF-04 | 当前可见海图activeMain≤1；高画质粒子精灵≤24，其中手机宽≤767px时≤12；同时逐格冲击簇≤4；流畅/减少动画粒子=0。一个Canvas也需计数内部精灵，不能用一个DOM规避预算。 |
| MV-PERF-05 | 新增效果活动DOM节点≤80，流畅≤24；减少动画无新增装饰动画节点。效果结束/取消后瞬态节点与句柄归零，允许一个可复用的空容器。 |
| MV-PERF-06 | 新增Canvas/纹理等效果层解码/绘制缓冲估算峰值≤24MiB，不含原舰体资产；画布DPR上限2，移动端默认上限1.5。仅用DOM/CSS同样报告使用位图解码估算；不强制为凑指标引入Canvas。 |

| MV-PERF-08 | 首页冷缓存首个可操作传输总量仍≤1.5MiB；本轮新增运行时JS+CSS原始合计增量≤120KiB；新增VFX压缩资源总量≤2MiB；首次高画质战斗新增全部静态图形仍≤10MiB。各预算同时成立，不能用gzip估算冒充实际网络传输。 |
| MV-PERF-09 | 战斗资源仅按阶段/类别预热，不在首页下载全部VFX；解码失败就用代码原语回退。首次选点和确认执行不能等贴图下载。过期请求完成不能重新挂载旧事件。 |
| MV-PERF-10 | 100次事件替换/取消+50次切图+50次抽屉+10次进出教程后，清理可回收状态，保留堆增长≤25%且无单调增长趋势；计时器/监听/活动动画数回到基线。无法取堆时附等效资源计数，不自动标记内存专项通过。 |
| MV-PERF-11 | 后台与减少动画无非必要rAF、环境计时器和持续绘制；倒计时、现有网络心跳不计作特效循环，但不得通过这些更新重建特效。 |
| MV-PERF-12 | 不出现未捕获异常、未处理拒绝、关键资源404、重复业务提交或无法点击的透明残层。负载超限先丢装饰，不丢事实、焦点、日志或命令确认锁。 |

### 12.1 证据采样方法

- 输入响应：输入事件到下一次包含正确状态的绘制，记录30次有效样本的原始时间与p95。
- 帧率：相同窗口连续10秒，包含环境+重复事件场景，注明刷新率、节能状态、CPU减速；报告平均fps与帧间隔p95。
- 长任务：事件开始前1秒至结束后1秒，记录最长任务及来源。
- 资源：冷缓存网络导出，区分代码、图像、声音；报告实际传输和未压缩体积。
- 生命周期：切页/后台/切画质后记录活动层、节点、粒子、Animation、rAF与延时句柄；不得记录凭证和私密room。
- 视觉：连续录屏或真实帧序列，包含t=0、主要节点、结束与取消；静态截图只能证明某一帧。

### 17.3 规则与协议的最小必读事实

- 10/12/15三图；7类8实例，两艘摩托艇独立；航母为5/6/8格四向连通、HP同为5/6/8，不强制直线；鱼雷2/3/5个。
- 部署180秒、行动90秒、重连120秒，服务器权威。每名玩家首个正常行动必须雷达，不能只看全局turnNumber===1。
- 三人一次意图，同坐标/区域对全部仍在局敌方同步结算；自己的消耗、自损一次，各敌方结果独立。
- 导弹/核弹命中对攻击方保密；震爆是否成功对攻击方保密。雷达仅是否有布局，探测仅是否有水下信号。
- 最终齐射秘密选择己方鱼雷，全员提交后同时结算；不能用动画顺序改变规则。更详细字段见现有安全投影和测试。
- 直升机由航空母舰提供，己方两艘驱逐舰沉没后解锁；不是可部署新单位。
- 部署后舰艇不移动；效果尾迹不应表现真实坐标变化。公开命中不等于暴露舰种/HP或一定扣血。
- Socket有room:state、room:sync、action:submit和final-salvo:submit等既有事件；本轮不新增效果专用秘密广播。
- 前端偏好键：ocean.reduce-motion.v1、ocean.theme.v1、ocean.accent.v1、ocean.quality.v1；音效/音乐及音量使用ocean.audio.*独立键。
- ocean.reconnect-session.v1包含roomCode与私密reconnectToken，禁止纳入录像可见内容、日志或效果数据。
- 私人标记按房间/自己ID/敌方ID分隔，本机存储，不消耗回合也不产生攻击效果。
