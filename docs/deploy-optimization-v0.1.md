# 《海战 OCEAN》阶段 10 渲染与可读性优化 v0.1

> 目录：Ocean-project-deploy-v0.1  
> 基线：Ocean-project-acceptance-v0.1  
> 规则与页面流程：完全冻结  
> 目标：消除部署页高频整页重绘，并提高全站文字可读性。

## 1. 问题根因

旧实现把 `hoverCoordinate` 保存在页面状态中。每次 `pointerover` 或部署格 `focusin` 都调用全局 `render()`，导致：

- `#app.innerHTML` 被完整替换；
- 100 个地图格、舰队列表、座位和工具栏全部重新创建；
- `.page-enter` 动画再次播放；
- 鼠标快速移动时形成连续重绘，表现为页面刷新、闪烁或滚动不稳；
- 切换兵种同样为了少量选中态变化而重建整页。

文字问题来自大量 0.55～0.75rem 的战术辅助文字。虽然信息密度较高，但在 14 英寸工作本和系统缩放环境中阅读负担过大。

## 2. 渲染优化

### 2.1 地图预览

`updateDeploymentPreview()` 直接在现有 100 格中：

1. 计算当前对象候选格；
2. 清除上一次合法/非法预览 class；
3. 只给本次候选格添加对应 class。

该过程不调用 `render()`，不更换地图节点，也不改变焦点。`pointerout` 离开地图时仅清除预览。

### 2.2 兵种切换

`updateDeploymentSelectionUi()` 只更新：

- 十项清单的 `fleet-item--selected` 和 `aria-pressed`；
- 已放置格的选中单位轮廓；
- 当前单位图标、名称和形状；
- 当前帮助文字；
- “撤回”按钮是否可用。

部署页、地图、滚动容器和其他表单节点保持原对象身份。

### 2.3 动画边界

全局渲染记录上一次 P01～P06/O05 页面编号。同一页面内部因服务器快照重绘时，在浏览器绘制前移除 `.page-enter`；只有真正切换页面才播放入场动画。

## 3. 重绘预算

| 操作 | 旧行为 | 当前行为 |
| --- | --- | --- |
| 鼠标移动到新部署格 | 整页 `innerHTML` | 仅候选格 class |
| Tab 聚焦新部署格 | 整页重绘并延时找回焦点 | 仅候选格 class，焦点原地保留 |
| 切换部署对象 | 整页 `innerHTML` | 六类局部文字/class/disabled 更新 |
| 点击实际放置 | 整页重绘 | 保留；部署结构已经变化 |
| 收到同阶段服务器快照 | 整页重绘并重复入场动画 | 整页同步但无重复入场动画 |
| P03 切换到 P04 | 整页重绘并入场 | 保留；属于正式页面转换 |

## 4. 字号基线

| 内容 | 新基线 |
| --- | ---: |
| 桌面根字号 | 17px |
| 600px 以下根字号 | 16px |
| 正文 | 1rem / 1.55 行高 |
| 普通按钮 | 0.92rem，最小高 42px |
| 手机按钮 | 最小高 44px |
| 主要列表名称 | 0.9rem |
| 辅助说明与状态 | 0.78～0.82rem |
| 地图坐标 | 0.72rem |
| 地图格内文字 | 0.68～0.82rem |

提高字号不改变 10×10 地图格数量。窄屏仍使用既有可滚动地图容器，优先保证信息可读而不是强行压缩文字。

## 5. 自动验证

- DOM 测试保存部署页和地图节点引用；切换兵种及连续移动两个目标格后，引用必须完全相同；
- 验证只有新候选格保留合法预览 class；
- CSS 通过浏览器样式表解析；
- 自动检查桌面、手机、按钮、舰队名称和地图文字的新字号下限；
- 既有整局、保密、断线、LAN、计时、终局和复盘测试继续运行。

## 6. 人工验收

自动测试不能判断主观阅读舒适度。请重点观察：连续快速扫图、页面滚动位置、键盘焦点、14 英寸屏幕正文、390px 窄屏按钮和双地图信息密度。

本轮确认后，下一子版本再根据当前托管产品的价格、WebSocket 限制、休眠策略和操作难度选择正式公网方案。
