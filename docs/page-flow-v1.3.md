## v1.3 多人流程补充

- P01 创建区增加“对战人数”选择，默认双人；房间人数创建后不可修改。
- P02 根据 `maxPlayers` 渲染 2 或 3 个席位；三人房间第二人加入后仍停留 P02，第三人加入后全员进入 P03。
- P04 全员掷骰，只有唯一最高点产生先手；最高点并列则全员重新展示一轮。
- P05 三人局在行动面板顶部显示“本回合攻击对象”。切换对象会切换敌方地图、攻击历史、侦察区域和私人标记，并清空尚未提交的目标格。

- 航空母舰沉没的玩家进入出局只读状态；回合顺序跳过出局玩家。剩余一名玩家时进入 P06。
- 终局鱼雷阶段仍为秘密提交；三人按固定座位顺序攻击下一名仍在局玩家，所有仍在局玩家提交后统一结算。
> 所属阶段：开发大纲第 3 步“设计页面与对局状态流程”  
> 边界：本文件只定义页面、交互、状态流转和信息可见性，不修改游戏规则，不包含程序代码。

## 1. 本阶段目标

本设计把已经冻结的游戏规则转换为后续可以直接实现和测试的产品流程，重点解决四件事：

1. 玩家在每个阶段能看到什么、能操作什么；
2. 房间、部署、掷骰、回合、暂停和结算如何流转；
3. 己方信息、敌方公开信息和敌方秘密信息如何隔离；
4. 超时、断线、自动跳过和终局手动鱼雷如何进入同一套状态模型。

本阶段确认后才建立项目。后续实现不得绕过本文定义的页面边界和状态流转。

## 2. 设计原则

1. **低成本实现**：首版采用单页应用，不引入前端框架和前端路由库。
2. **服务器权威**：客户端只显示服务器状态并提交意图；倒计时、命中、伤害、弹药和胜负均不由客户端决定。
3. **信息最小化**：对局结束前，服务器不给客户端发送任何不应看到的敌方部署信息。
4. **先清楚后华丽**：动画只辅助表达，不能阻塞或改变真实结算。
5. **桌面优先、手机可用**：桌面同时显示两张地图；手机通过标签切换两张地图。
6. **操作可撤销到提交前**：部署和目标选择可取消；行动一旦被服务器接受便不可撤销。
7. **不用颜色作为唯一提示**：命中、未命中、不可用、倒计时等状态同时使用图形或文字。

## 3. 应用入口与页面组织

### 3.1 地址设计

首版只使用一个 HTML 入口：

- 首页地址：/
- 房间地址：/?room=ABC123

创建或加入房间后，浏览器地址更新为带房间码的形式。刷新页面时，客户端使用本机保存的私密重连凭证向服务器恢复座位。没有有效凭证时，只能作为新玩家申请加入，不能恢复他人座位。

选择查询参数而不使用复杂路由，是为了减少部署配置和刷新页面时的服务器处理。

### 3.2 页面与覆盖层

| 编号 | 正式名称 | 类型 | 对应阶段 | 主要用途 |
| --- | --- | --- | --- | --- |
| P01 | 进入游戏页 | 页面 | 未进入房间 | 输入昵称、创建房间、加入房间 |
| P02 | 房间等待页 | 页面 | WAITING | 展示房间码和玩家席位，等待第二名玩家 |
| P03 | 舰队部署页 | 页面 | DEPLOYING | 部署舰队、随机部署、准备 |
| P04 | 掷骰决定先手页 | 页面 | ROLLING | 展示服务器骰子和先手结果 |
| P05 | 对战页 | 页面 | PLAYING | 查看地图、选择行动、提交目标、查看记录 |
| P06 | 对局结算页 | 页面 | FINISHED | 展示胜负、完整复盘、再来一局 |
| O01 | 规则说明层 | 覆盖层 | 任意非提交时刻 | 查看精简规则和图例 |

                     ┌────────┴────────┐

## 4. 服务器状态模型

为避免把“对局阶段”“回合处理”和“连接状态”混成一个巨大的状态枚举，服务器状态分为三条互相配合的状态轴。

### 4.1 房间阶段 roomPhase

| 状态 | 含义 | 允许的主要操作 | 下一状态 |
| --- | --- | --- | --- |
| WAITING | 房间不足两名玩家 | 加入、复制房间码、离开 | DEPLOYING 或 CLOSED |
| DEPLOYING | 两名玩家部署舰队 | 放置、旋转、撤回、随机部署、准备 | ROLLING 或 CLOSED |
| ROLLING | 部署锁定，服务器决定先手 | 无游戏操作，只展示结果 | PLAYING |
| PLAYING | 正式对战进行中 | 当前玩家提交一个合法行动；双方可投降 | FINAL_SALVO、FINISHED 或 CLOSED |
| FINAL_SALVO | 双方手动逐枚引爆剩余鱼雷 | 每轮秘密选择 1 枚；双方提交后同时结算 | FINISHED |
| FINISHED | 本局已结束 | 复盘、申请再来一局、离开 | DEPLOYING、WAITING 或 CLOSED |
| CLOSED | 房间已关闭或对局已取消 | 返回首页 | 无 |

### 4.2 回合阶段 turnPhase

turnPhase 只在 roomPhase 为 PLAYING 时存在。

| 状态 | 含义 | 是否运行 90 秒计时 |
| --- | --- | ---: |
| ACTIVE | 当前玩家可以选择并提交行动 | 是 |
| RESOLVING | 服务器正在验证并原子结算行动 | 否 |
| AUTO_SKIPPING | 当前玩家没有合法行动，服务器自动跳过 | 否 |

回合计数在进入 ACTIVE 时增加一次。行动超时仍属于一个实际行动回合，因此计入回合数；因全部可用行动来源瘫痪或其他原因触发的无合法行动自动跳过没有给予行动机会，不计入回合数，但必须写入行动记录。

### 4.3 连接状态 connectionPhase

| 状态 | 含义 | 页面表现 |
| --- | --- | --- |
| CONNECTED | 当前需要在线的玩家均在线 | 正常显示当前页面 |
| PAUSED_ONE_OFFLINE | 一名玩家离线 | 阻塞操作，显示离线方和 120 秒服务器倒计时 |
| PAUSED_BOTH_OFFLINE | 两名玩家均离线 | 服务器保留状态；任一方重连后重新同步 |

连接状态不会自行改变 roomPhase。只有服务器根据 120 秒规则作出关闭房间、取消对局或判负后，roomPhase 才进入 CLOSED 或 FINISHED。

### 4.4 状态转换约束

1. 所有阶段转换只能由服务器产生，客户端不能自行跳页。
2. 客户端收到完整状态快照后，根据 roomPhase 选择 P02～P06。
3. RESOLVING 期间按钮全部锁定，避免重复提交；相同行动编号即使重复到达服务器也只结算一次。
4. 骰子、范围攻击和每轮终局鱼雷均由服务器权威结算，再把安全结果发给客户端。
5. 服务器发送绝对截止时间，客户端只负责显示剩余时间；刷新或后台挂起后重新按服务器时间校正。
6. 每次状态消息包含单调递增的状态版本号；客户端忽略比当前版本旧的消息。

### 4.5 胜负与终局检查顺序

服务器在一个原子结算点只产生一个最终阶段转换，并严格按冻结规则的优先级检查：

1. 已接受的攻击行动结算后，若任一航空母舰生命值降至 0，立即按规则确定唯一胜方并进入 FINISHED；
   - 海盗船行动结算后，若敌方航空母舰沉没，海盗船一方获胜；即使双方航空母舰同时沉没也不改变结果；
   - 海盗船行动结算后，若只有己方航空母舰沉没，海盗船一方失败；
   - 其他攻击行动按“摧毁敌方航空母舰者获胜”处理；
2. 若没有发生“攻击行动摧毁航空母舰”，再处理已经确认的投降；
3. 行动截止时，若连续行动超时达到 3 次，进入 FINISHED；
4. 断线等待截止时，按在线人数决定判负或取消；
5. 每次合法行动结算且未产生以上结果后，若双方均无攻击手段，进入 FINAL_SALVO；
6. 以上条件均不成立时，才切换下一正常回合。

客户端动画不得改变这个顺序，也不能在普通攻击已经摧毁航空母舰后再启动终局手动鱼雷。

## 5. P01 进入游戏页

### 5.1 页面结构

- 游戏名称与一句话说明；
- 昵称输入框，长度提示为 1～12 个字符；
- “创建房间”按钮；
- 6 位房间码输入框；
- “加入房间”按钮；
- “游戏规则”入口；
- 若检测到本机尚有效的重连凭证，顶部显示“恢复上次对局”卡片。

### 5.2 交互规则

1. 昵称去除首尾空白后验证，不能为空且不能超过 12 个字符。
2. 房间码输入统一转为大写，只接受 6 位服务器允许字符。
3. 点击按钮后进入提交中状态，防止连续创建或加入。
4. 创建成功后写入房间码和私密重连凭证，并进入 P02。
5. 加入成功后由服务器阶段决定进入 P02 或 P03。
6. 房间不存在、已满或对局已开始时，停留在本页并显示明确原因。
7. 房间码不显示为密码，也不能代替重连凭证。

## 6. P02 房间等待页

### 6.1 页面结构

- 房间码和“复制房间码”按钮；
- 两个玩家席位卡：昵称、在线状态、是否已进入；
- “等待另一名玩家”状态；
- “离开房间”按钮；
- 精简规则入口。

等待阶段不显示部署地图，不提前启动 180 秒倒计时。第二名玩家成功加入后，服务器进入 DEPLOYING，双方同时切换到 P03。

### 6.2 断线

对局开始前有玩家断线时保留座位 120 秒。断线期间 O02 覆盖当前页；超时未返回时服务器关闭房间，在线方进入 O05。

## 7. P03 舰队部署页

### 7.1 桌面布局

    ┌──────────────── 顶部：房间码、双方状态、180 秒 ────────────────┐
    │                                                               │
    │  左侧：舰队清单与状态       中部：10×10 己方地图       右侧：操作说明 │
    │                                                               │
    ├───────────────────────────────────────────────────────────────┤
    │  随机部署   清空部署   旋转   撤销   准备/取消准备   离开房间    │
    └───────────────────────────────────────────────────────────────┘

手机端按“舰队清单—地图—底部操作栏”纵向排列，地图保持正方形。

### 7.2 舰队清单

清单固定展示七个作战单位和三个诱饵鱼雷。每项显示：

- 正式名称；
- 占地形状；
- 已放置或未放置；
- 当前朝向；
- 选中状态。

此阶段不需要展示生命值和弹药，因为所有资源均为初始值。

### 7.3 放置方式

| 对象 | 桌面操作 | 手机操作 | 有效预览 |
| --- | --- | --- | --- |
| 直线单位 | 从清单拖到地图，或选中后点击起点 | 选中单位后点击起点 | 绿色表示合法，红色表示越界或重叠 |
| 潜水艇、核潜艇 | 拖放完整 2×2 方形 | 选中后点击左上角 | 显示完整 2×2 轮廓 |
| 摩托艇、诱饵鱼雷 | 拖放或单击目标格 | 选中后点击目标格 | 显示单格轮廓 |
| 航空母舰 | 选中后依次选择 6 个四向连通格 | 同桌面 | 已选格高亮；不连通的下一格不可选 |

补充交互：

1. 旋转按钮将选中直线单位旋转 90 度；桌面同时支持 R 键。
2. 已放置对象可拖到新位置；非法落点恢复原位置。
3. 已完成的航空母舰可整体拖动或旋转；若新位置非法则恢复原状。
4. 点击已放置对象后可“撤回”；航空母舰编辑时也可撤销最后一个格。
5. “随机部署”生成整套合法部署；若当前已有手动部署，先二次确认是否覆盖。
6. “清空部署”需二次确认。
7. 客户端即时预览只用于便利；点击“准备”时服务器再次完整验证。

### 7.4 准备按钮状态

| 本方部署 | 本方准备 | 对方准备 | 按钮 |
| --- | --- | --- | --- |
| 不完整或非法 | 否 | 任意 | “准备”禁用，并列出缺失项 |
| 完整合法 | 否 | 任意 | “准备”可用 |
| 已准备 | 是 | 否 | 显示“取消准备”，可用 |
| 已准备 | 是 | 是 | 部署锁定，按钮禁用 |

本方准备后地图进入只读状态。若取消准备成功，地图恢复编辑。双方都准备后由服务器立刻锁定部署并进入 ROLLING，任何延迟到达的取消请求都应被拒绝。

180 秒结束时，服务器随机补全尚未准备玩家的合法部署并自动准备。页面显示“部署时间结束，服务器已自动完成部署”，随后进入 P04。

## 8. P04 掷骰决定先手页

页面同时显示双方昵称、骰子和当前轮次。

流程如下：

1. 服务器一次性生成双方点数；
2. 客户端播放约 1 秒的骰子动画；
3. 显示两点数；
4. 若相同，显示“点数相同，重新掷骰”，然后展示下一组服务器结果；
5. 分出大小后显示“某玩家获得第一回合”；
6. 短暂停留后由服务器状态切换到 P05。

动画期间没有可影响随机数的按钮。玩家刷新页面时直接恢复服务器已经确定的最终结果，不重新生成骰子。

## 9. P05 对战页

### 9.1 桌面布局

    ┌──────── 房间码 | 双方昵称与在线状态 | 当前回合 | 90 秒 ────────┐
    │                                                               │
    │  己方地图 10×10       敌方地图 10×10       行动与单位状态面板   │
    │                                                               │
    ├───────────────────────────────────────────────────────────────┤
    │  公开行动记录                         规则   投降               │
    └───────────────────────────────────────────────────────────────┘

### 9.2 手机布局

- 顶部固定显示当前回合和倒计时；
- 使用“敌方地图 / 己方地图”两个标签切换地图；
- 默认进入敌方地图，受到新攻击时在己方地图标签显示提醒点；
- 行动面板放在底部抽屉，可展开或收起；
- 行动记录为可折叠区域；
- 不依赖鼠标悬停，所有预览都支持点击。

### 9.3 顶部对局状态

顶部必须始终显示：

- 当前行动玩家；
- 本方是“你的回合”或“等待对方”；
- 服务器同步的剩余秒数；
- 双方在线状态；
- 本方连续行动超时次数；
- 当前总回合数。

倒计时在 30 秒时进入警告样式，10 秒时进入紧急样式，但不播放连续刺耳声音。

### 9.4 己方地图

己方地图显示：

- 全部己方作战单位及正式名称或图形；
- 三个诱饵鱼雷及其有效或已摧毁状态；
- 各单位格的未受击、已受击、残骸和本回合瘫痪状态；
- 当前行动来源对应的单位轮廓；
- 驱逐舰行动被选中时，在己方图上突出其中心格或两个中间格。

地图旁的单位状态卡显示本方生命值、剩余弹药、存活/沉没、瘫痪状态和行动可用原因。被震爆弹影响的单位显示“瘫痪：本回合不能行动”；敌方永远看不到这些状态卡。

### 9.5 敌方地图基础状态与潜射标记

每个敌方地图格只有三种互斥基础状态：

| 基础状态 | 视觉内容 | 是否可作为单格攻击目标 |
| --- | --- | ---: |
| 未知 | 海面底色 | 是，但仍需满足具体攻击范围 |
| 命中 | 红色命中图形和文字替代提示 | 否 |
| 未命中 | 浅色水花或叉号 | 否 |

攻击方敌方地图永远不显示沉没、舰种、剩余生命值、完整轮廓或诱饵身份。

“导弹已发射”不是第四种基础状态，而是覆盖在“未知”基础状态上的独立潜射标记：

- 潜射导弹发射后，目标格显示“导弹已发射”，不显示命中或未命中；
- 只有该标记的格仍可成为单格攻击目标；
- 范围攻击不会因为该标记而跳过该格；
- 若后续其他行动公开得出“命中”或“未命中”，该格转为相应基础状态；潜射历史仍保留在行动记录中。

### 9.6 情报覆盖层

探测弹和震爆弹不会改变基础状态，两者分别形成独立的区域记录：

- 探测弹记录中心格、3×3 作用区域、布尔探测结果和发生回合；
- 震爆弹记录中心格、5×5 作用区域和发生回合，不记录成功或失败；
- 地图默认以淡色边框显示最近一次探测或震爆区域；
- 点击行动记录可重新高亮对应的 3×3 或 5×5 区域；
- 多个区域重叠时不合并结果，也不覆盖更早记录；
- 情报区域中的格仍可正常成为攻击目标，只要基础状态为未知且符合行动范围。

### 9.7 私人标记 O

1. 敌方地图提供“标记模式”按钮；桌面另支持 M 键切换。
2. 标记模式下点击未知格可添加或取消 O，不提交游戏行动。
3. 普通目标选择模式和标记模式互斥，避免误操作。
4. 某格收到命中或未命中公开结果后，该格上的 O 自动删除。
5. 私人标记只保存在本机浏览器，并随同一设备重连恢复；不发送给对手。

### 9.8 单元格视觉优先级

同一格出现多个显示状态时，从高到低按以下顺序绘制：

1. 当前目标和即将作用的范围预览；
2. 命中或未命中基础状态；
3. “导弹已发射”潜射标记；
4. 私人标记 O；
5. 当前选中的探测或震爆情报边框；
6. 海面底色。

该优先级只影响显示，不改变服务器状态。

## 10. 行动选择与提交

### 10.1 客户端交互状态

当前玩家的操作按以下步骤流转：

    未选择行动
         ↓ 选择可用行动
    正在选择目标
         ↓ 选择合法格、行或列
    等待确认
       ├─ 取消 → 正在选择目标
       └─ 确认 → 正在提交
                       ↓
                  等待服务器结算
                    ├─ 拒绝 → 返回选择并显示原因
                    └─ 接受 → 展示结果并结束回合

在“等待确认”之前不消耗行动或弹药。服务器接受行动后，即使客户端断线，结算也必须完成。

### 10.2 行动卡状态

每个行动卡只能是以下一种状态：

- 可用：本方回合且满足来源、弹药、解锁和合法目标条件；
- 等待回合：行动本身可用，但当前不是本方回合；
- 已沉没：行动来源已沉没；
- 瘫痪：行动来源本回合受震爆影响，并显示“该单位本回合不能行动”；
- 弹药耗尽：有限资源为 0；
- 尚未解锁：只用于直升机扫射，并显示“己方两艘驱逐舰均沉没后解锁”；
- 无合法目标：仅用于两艘驱逐舰的范围内坐标均已被驱逐舰尝试过，或所选范围本身无有效坐标；
- 提交锁定：服务器正在处理上一请求。

禁用状态必须显示文字原因，不能只变灰。

### 10.3 各行动的目标界面

| 行动 | 选择方式 | 合法目标预览 | 确认信息 |
| --- | --- | --- | --- |
| 驱逐舰Ⅰ冲撞 | 选择 1 格 | 7×7 内且未被任一驱逐舰攻击过 | 行动名称、目标格、自身可能受伤 |
| 驱逐舰Ⅱ冲撞 | 选择 1 格 | 8×8 内且未被任一驱逐舰攻击过 | 行动名称、目标格、自身可能受伤 |
| 海盗船攻击 | 选择 1 格 | 全图任意格 | 命中单位时目标 −2、海盗船 −1；海盗船实际受伤时己方航母 −0.5 |
| 摩托艇冲撞 | 选择 1 格 | 全图任意格，可重复选择 | 行动名称、目标格；命中水面单位或诱饵鱼雷后自身沉没 |
| 潜射导弹 | 选择 1 格 | 全图任意格，可重复选择 | 行动名称、目标格、提交后剩余枚数；明确提示发射方不会获知结果 |
| 核弹 | 选择 1 格 | 全图任意格 | 只显示“核弹已投放”和剩余枚数，不显示命中情况 |
| 震爆弹 | 选择中心格 | 只允许 C3～H8，并预览完整 5×5 | 行动名称、中心格、5×5 区域、提交后弹药耗尽；明确提示不会返回是否生效 |
| 探测弹 | 选择中心格 | 只允许 B2～I9，并预览完整 3×3 | 行动名称、中心格、提交后弹药耗尽 |
| 直升机扫射 | 先选“行”或“列”，再选坐标 | 高亮完整 10 格，只弱化命中或未命中的已结算格 | 行动名称、整行或整列；只命中水面单位，对航空母舰本次总伤害最多为 2 |

选择驱逐舰行动时，己方地图同时显示范围中心；敌方地图只显示可选格，不绘制任何敌方秘密信息。

海盗船确认层说明：成功命中任一作战单位时目标 −2、海盗船 −1；命中诱饵时诱饵被摧毁、海盗船受爆炸伤害 1；海盗船每次实际受伤使己方航空母舰联动损失 0.5；未命中无伤害。

摩托艇确认层须说明：只有命中航空母舰时目标受到 1 点伤害；命中其他水面单位只返回命中而不伤害目标；命中水面单位或诱饵鱼雷后摩托艇自身沉没；潜水艇和核潜艇不属于可命中对象。

直升机扫射只能选择至少包含一个未结算格的行或列；十格均已结算的行或列显示为不可选。只有潜射标记的格仍属于未结算格，必须正常进入扫射结算。扫射只命中水面单位，不命中水下单位或诱饵鱼雷；同一次扫射对航空母舰的总伤害上限为 2，但覆盖到的所有未结算航空母舰单位格仍分别显示命中。

### 10.4 行动结果反馈

1. 除潜射导弹外，单格攻击只向攻击方显示“命中”或“未命中”，不显示敌方舰种、伤害或沉没。
2. 潜射导弹结算后，发射方只看到目标格新增“导弹已发射”标记，不收到命中、未命中、目标类型、伤害或沉没信息。
3. 防守方始终看到“对方使用潜射导弹攻击了某格”；若命中，防守方正常看到己方单位受伤、沉没或诱饵鱼雷被摧毁；若未命中，不再显示任何附加结果。
4. 潜射标记不把格子变为已结算格。该格可被再次单格攻击，范围攻击也正常处理；若同一单位格此前已被潜射导弹实际命中，服务器仍执行后续行动反馈，但不得从该单位格重复扣除生命值。
5. 直升机扫射逐格更新命中或未命中，已结算格保持原状态，只有潜射标记的格照常结算。
6. 探测弹只显示“探测到水下信号”或“未探测到水下信号”。
7. 震爆弹施加方只看到行动已使用、中心格和 5×5 作用区域，不显示“震爆成功”或“震爆失败”，也不显示受影响单位的数量、类型或坐标。
8. 震爆弹防守方在己方地图和单位状态卡中看到实际被瘫痪的潜水艇或核潜艇；全部水面单位和诱饵鱼雷不受影响。
9. 防守方在己方状态卡上看到自己实际生命值变化、沉没和瘫痪状态。
10. 海盗船行动造成的海盗船自身伤害和己方航空母舰伤害必须向该玩家正常显示。服务器不直接公开敌方目标类型，但玩家可以依据己方实际状态变化自行推断。
11. 动画总时长应短，玩家可关闭动画；跳过动画不跳过服务器结算。

### 11.1 双方可见的公开行动记录

每条记录包含：

- 行动玩家昵称；
- 正式行动名称；

- 己方单位沉没；
- 己方诱饵鱼雷被摧毁；

- 己方剩余弹药和行动可用状态；
- 非法请求的具体拒绝原因。

对局结束进入 FINISHED 后，双方获得完整复盘记录，不再执行上述隐藏。

## 13. 自动流程和异常流程

### 13.1 行动超时

1. ACTIVE 的 90 秒截止时仍无已接受行动，服务器结束当前回合；
2. 公开记录写入“行动超时”；
3. 该玩家连续超时次数加 1；
4. 达到 3 次时直接进入 FINISHED，对方获胜；
5. 未达到 3 次时切换到另一玩家；
6. 任意一次合法行动完成后，该玩家连续超时次数清零。

客户端倒计时到 0 只能显示等待状态，最终是否超时以服务器消息为准。

### 13.2 震爆瘫痪回合

防守方下一个正常回合开始时，服务器应用待生效的单位级瘫痪：

1. 5×5 区域曾覆盖任意单位格的存活潜水艇或核潜艇，整艘水下单位显示“瘫痪：本回合不能行动”；水面单位和诱饵鱼雷不受影响；
2. 瘫痪单位对应的行动卡禁用，未瘫痪单位仍按通常条件判断是否可用；
3. 若至少存在一个由未瘫痪单位发动的合法行动，进入 ACTIVE 并正常启动 90 秒计时；
4. 该玩家使用未瘫痪单位完成行动后，本次震爆造成的全部瘫痪立即解除；
5. 若本回合不存在任何合法行动，进入 AUTO_SKIPPING，不启动计时、不增加连续超时次数；自动跳过后解除全部瘫痪；
6. 公开记录只写“当前玩家没有可用行动，本回合自动跳过”，不得列出瘫痪单位或直接显示震爆是否成功。

### 13.3 无合法行动自动跳过

若当前玩家没有任何合法行动，但对方仍有合法行动：

1. 进入 AUTO_SKIPPING；
2. 显示“当前没有合法行动，回合自动跳过”；
3. 不启动 90 秒计时，不增加连续超时次数；
4. 切换到另一玩家。

若双方都没有攻击手段，优先进入 FINAL_SALVO，而不是让双方无限自动跳过。服务器必须防止自动跳过形成死循环。

瘫痪属于只持续一个回合的临时状态，不得据此判定某方永久失去攻击手段，也不得仅因当前全部行动来源瘫痪而提前进入 FINAL_SALVO。

### 13.4 终局手动鱼雷引爆

进入 FINAL_SALVO 后：

1. 普通行动面板锁定，己方地图中的未触发鱼雷变为可选按钮；
2. 每轮每方秘密提交一枚；界面只显示“己方已提交/对方已提交”，不泄露对方所选坐标；
3. 双方都提交后服务器同时结算本轮并移除已引爆鱼雷；无鱼雷方自动跳过；
4. 若仍有可用鱼雷，增加轮次并继续选择；全部耗尽后展示双方航空母舰最终生命值；
5. 按服务器结果进入 FINISHED。刷新只恢复服务器确认的当前轮次，不重复结算。

刷新页面或跳过动画时直接显示已完成的齐射结果，不重复发射。

### 13.5 非法行动与重复提交

- 非法行动不结束回合、不消耗弹药，客户端显示服务器具体原因；
- 若是状态已过期，客户端立即请求最新完整快照；
- 网络重试必须复用同一个行动编号；
- 服务器返回该编号原有结果，而不是再次结算；
- 提交期间客户端不能再选择第二个行动。

### 13.6 投降

投降按钮在 roomPhase 为 PLAYING 时显示。在线玩家即使正在等待断线方重连，也可以在 O02 中选择“投降并离开”。点击后弹出二次确认，明确写出“投降后本局立即失败，无法撤销”。

服务器按顺序处理已经接受的事件：若一个攻击行动已经进入 RESOLVING，先完成该行动；若它已经按更高优先级摧毁航空母舰，则按该攻击行动的胜负结算，否则再接受投降并进入 FINISHED。

### 13.7 海盗船特殊胜负

海盗船攻击必须在一次原子结算中同时更新目标、海盗船和海盗船受伤触发的己方航空母舰联动伤害，再决定胜负：

- 敌方航空母舰沉没时，海盗船一方获胜；
- 双方航空母舰同时沉没时，仍判海盗船一方获胜；
- 只有己方航空母舰沉没时，海盗船一方失败。

## 14. 断线与重连流程

### 14.1 通用显示

一名玩家断线后，在线玩家看到 O02：

- 哪位玩家已断线；
- 服务器剩余等待时间；
- “正在等待重连，当前操作已暂停”；
- 对局开始前显示“离开房间”；对局开始后显示“投降并离开”，不使用含义模糊的“返回首页”。

断线玩家重连时先看到“正在恢复对局”，收到完整安全快照后再显示当前页面。

### 14.2 对局开始前

WAITING、DEPLOYING 和 ROLLING 均按“对局开始前”处理：

- 断线方座位保留 120 秒；
- 暂停当前页面的可操作内容；
- DEPLOYING 的 180 秒倒计时暂停，重连后按服务器剩余时间继续；
- 断线期间不进入 ROLLING 或 PLAYING；
- 超时未返回时进入 CLOSED，不判胜负。

### 14.3 对局开始后

PLAYING 和 FINAL_SALVO 按“对局开始后”处理：

- 任一方断线立即暂停；
- 当前行动倒计时冻结，重连后按服务器保存的剩余时间继续；
- 120 秒内重连则从服务器确认状态继续；
- 一方在线而另一方超时，断线方判负并进入 FINISHED；
- 双方均离线且均未按时返回，进入 CLOSED，并标记“对局取消，不判胜负”。

断线发生在行动已经被服务器接受之后，该行动必须先完成原子结算；重连后从结算后的状态继续，不能回滚或重复行动。

## 15. P06 对局结算页

### 15.1 结果摘要

- 胜利、失败或平局；
- 唯一胜负原因；
- 对局总回合数；
- 对局持续时间；
- 双方最终航空母舰生命值；
- “再来一局”和“离开房间”按钮。

若由海盗船特殊规则结束对局，胜负原因必须明确显示“海盗船攻击使敌方航空母舰沉没”或“海盗船攻击仅使己方航空母舰沉没”，双方同时沉没时注明“按海盗船特殊规则，海盗船一方获胜”。

### 15.2 完整复盘

结算后提供两个地图标签，公开：

- 双方完整部署和所有对象真实身份；
- 最终生命值；
- 剩余弹药；
- 所有单位格受击状态和残骸；
- 完整行动记录；
- 终局每轮鱼雷选择、目标与同时伤害（若发生）。

公开记录与复盘信息分栏展示，避免把对局中可见信息和结算后揭示信息混为一体。

### 15.3 再来一局

| 本方选择 | 对方状态 | 页面反馈 |
| --- | --- | --- |
| 未选择 | 未选择 | “再来一局”可用 |
| 已选择 | 未选择 | “已申请，等待对方”并允许取消 |
| 已选择 | 已选择 | 服务器进入 DEPLOYING，清空上局部署和资源 |
| 任一方离开 | 另一方留下 | 留下方进入 WAITING，可重新邀请玩家 |

双方确认再来一局后必须重新部署、恢复初始资源并重新掷骰；只保留昵称、房间和玩家座位。

## 16. 视觉与可用性基线

### 16.1 视觉方向

- 风格：深海战术界面；
- 主背景：深海军蓝；
- 可交互强调：青蓝；
- 命中：红色加爆点图形；
- 未命中：浅灰蓝加水花或叉号；
- 导弹已发射：黄色或橙色导弹图标，并配同名文字提示；
- 瘫痪：仅在己方单位上使用紫色电弧或禁用图标，并配“本回合不能行动”文字；
- 警告：橙色；
- 字体：优先使用系统中文字体，不下载大型字体文件；
- 舰艇和状态图形优先使用 CSS、简单 SVG 或轻量本地资源。

最终配色在写界面时可以微调，但状态含义不能改变。

### 16.2 可用性要求

1. 10×10 地图坐标 A～J 和 1～10 始终可见。
2. 桌面端单格点击区域不小于 36×36 像素；手机端尽量不小于 32×32 像素。
3. 所有按钮有正常、悬停、聚焦、禁用和提交中状态。
4. 键盘可以聚焦地图格并确认选择；焦点边框清晰。
5. 重要弹窗初始焦点放在安全按钮，例如“取消”。
6. 页面刷新、窗口缩放和手机横竖屏切换不能改变游戏状态。
7. 低性能设备可关闭动画，且不影响任何功能。

## 17. 错误信息规范

错误信息必须说明原因和下一步，不使用单独的“失败”。

| 场景 | 推荐文本 |
| --- | --- |
| 房间不存在 | “未找到该房间，请检查 6 位房间码。” |
| 房间已满 | “该房间已有两名玩家。” |
| 对局已开始 | “该房间的对局已经开始，不能加入。” |
| 部署不完整 | “还有以下对象未部署：……” |
| 部署非法 | “部署重叠或越界，请调整红色标记区域。” |
| 非本人回合 | “当前不是你的回合，已同步最新对局状态。” |
| 目标已结算 | “该格已有命中或未命中结果，请选择未知格。” |
| 超出攻击范围 | “目标不在该行动的攻击范围内。” |
| 弹药不足 | “该行动的弹药已经用完。” |
| 行动来源沉没 | “行动来源已经沉没，不能发动行动。” |
| 行动来源瘫痪 | “该单位本回合处于瘫痪状态，请选择其他可用单位。” |
| 网络中断 | “与服务器的连接已中断，正在尝试重连。” |
| 房间被关闭 | “玩家未在 120 秒内返回，房间已关闭。” |

只有“导弹已发射”标记而没有命中或未命中基础状态的格，不得触发“目标已结算”错误。

## 19. 已确认的五项设计决定

以下决定不修改游戏数值或胜负规则，但会影响后续实现。v1.2 固定采用：

1. 使用单页应用和 /?room=ABC123，不引入前端路由库；
2. 每个行动都采用“选择目标—确认提交”两步，减少误触；
3. 手机端以标签切换己方地图和敌方地图，不强行并排缩小；
4. 私人标记 O 只保存在本机浏览器，不进入服务器战局数据；
5. 对局开始前有人断线时暂停部署倒计时并阻止进入掷骰或对战。

用户已确认这五项及全文，本文件正式冻结为页面与流程设计 v1.0。后续实现必须遵守本文件；如需改变页面边界或状态流程，应另行形成新版本，不在代码中私自修改。
