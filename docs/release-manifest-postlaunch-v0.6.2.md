# 《海战 OCEAN》postlaunch-v0.6.2 发布清单

> 版本：0.6.2  
> 阶段：postlaunch-v0.6.2  
> 规则：rule-v1.4  
> 页面流程：page-flow-v1.4  
> Socket：1.5 / socket-protocol-v0.8  
> 基线：postlaunch-v0.6.1

## 1. 发布目标

本版只修订三人对战回合与终局鱼雷语义，并补齐对应服务器状态、信息投影、客户端最小交互与测试。UI 大改留给后续版本，不在本版重新设计视觉界面。

## 2. 三人正常回合

- 当前玩家需要分别对每名仍在局敌方玩家完成一次普通操作；
- A 面对 B、C 时可以采用任意合法组合，例如：
  - 驱逐舰 → B，潜射导弹 → C；
  - 震爆弹 → B，核弹 → C；
  - 海盗船 → B，海盗船 → C（若结算后来源仍可行动且规则允许）；
- 第一项操作完成后保持同一 `currentPlayerId`、同一 `turnNumber` 与同一 90 秒截止时间；
- 同一回合不能用两次普通操作都针对同一名敌人来代替另一名敌人的操作；
- 若剩余目标在本回合中出局，自动从本回合目标集合移除；
- 若结算后已经不存在作用于剩余目标的合法行动，则正常结束回合，不制造虚假操作。

## 3. 特殊例外

### 直升机

- 三人局直升机必须作为该回合首个且唯一行动；
- 同一行/列同时在所有仍在局敌方地图上独立结算；
- 只消耗 1 次直升机；
- 一次性完成全部本回合目标；
- 若已经先执行普通行动，再使用直升机必须被服务器拒绝。

### 首次雷达

- 现有首次雷达规则保留；
- 三人局第一项操作必须雷达扫描一名敌方玩家；
- 雷达只完成该名敌人的操作，随后仍需对另一名敌人完成一次合法操作。

### 终局手动鱼雷

- 每轮每名仍在局玩家仍只选择 1 枚己方未引爆诱饵鱼雷；
- 三人局该鱼雷同时攻击其他全部仍在局玩家的同名坐标；
- 选择仍保持秘密提交、整轮统一结算。

## 4. 状态与协议

`room:state.turn` 增加/明确：

- `requiredTargetPlayerIds`
- `completedTargetPlayerIds`
- `remainingTargetPlayerIds`
- `actionCount`

多目标行动记录支持：

- `defenderIds`
- `cellResultsByDefender`

协议版本更新至 1.5。

## 5. 独立敌方地图

三人局对每名敌方玩家分别维护：

- 命中 / 未命中；
- 驱逐舰已攻击坐标；
- 潜射导弹标记；
- 核弹标记；
- 侦察/震爆/雷达区域；
- 客户端私人标记。

B、C 的记录不得互相污染。

## 6. 生命周期与计时

- 两次普通操作共享一个 90 秒玩家回合；
- 第一项完成后不重置计时；
- 回合超时时已完成操作不回滚；
- 连续超时按完整玩家回合计数；
- 三人回合第一项操作后瘫痪状态不提前清除，直到整个玩家回合结束；
- 投降/断线超时导致剩余目标出局时，本回合目标集合实时收缩。

## 7. 前端最小兼容

本版只做保证新规则可玩的最小前端适配：

- 三人行动时只允许选择当前 `remainingTargetPlayerIds`；
- 第一项操作后自动切换/提示剩余目标；
- B、C 使用各自 `enemyMapsByPlayer`；
- 三人全局直升机确认与结果支持多目标；
- 三人地图折叠、现代化布局和完整视觉改造不在本版实施，留待后续 UI 专项版本。

## 8. 发布验收

发布前至少验证：

- [ ] 双人原有流程与规则全部保持；
- [ ] A 能在同一回合分别对 B、C 各操作一次；
- [ ] 第一项后仍是 A，且回合号和截止时间不变；
- [ ] B、C 两张敌方地图记录相互独立；
- [ ] 两次操作可采用任意合法组合；
- [ ] 同一回合不能重复普通操作同一目标；
- [ ] 首次雷达只完成一个敌方目标，随后继续第二目标；
- [ ] 直升机同时作用 B、C 并直接结束回合；
- [ ] 已执行普通行动后直升机被拒绝；
- [ ] 90 秒在两次操作间不重置；
- [ ] 第一项操作后瘫痪不提前清除；
- [ ] 剩余目标中途出局时当前回合正确继续或结束；
- [ ] 终局手动鱼雷每次选择同时作用所有其他仍在局玩家；
- [ ] 信息隐藏与 v0.6.1 保持一致；
- [ ] `npm run check` 通过；
- [ ] Node 24 环境 `npm run acceptance` 全部通过。
