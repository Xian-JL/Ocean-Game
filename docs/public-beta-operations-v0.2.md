# 公网测试运行边界 v0.2

## 当前能够做到

- 两名玩家不必位于同一局域网，可通过同一个 HTTPS 地址和房间邀请链接对战；
- Render 负责公网入口、TLS 证书和 WebSocket 转发；
- 服务器继续权威校验部署、行动、伤害、隐藏信息和胜负；
- 浏览器 Socket.IO 握手只接受同源站点，HTTP 页面附带基础安全响应头；
- 短暂网络波动仍沿用现有私密重连凭证和断线裁决流程。

## 必须接受的限制

房间、对局和重连凭证目前只保存在单个 Node.js 进程内。以下情况会使全部当前房间不可恢复：

- Render 重启或替换实例；
- 发布新版本或手动重启服务；
- 免费实例休眠后重新唤醒；
- 进程崩溃。

因此 v0.2 适合邀请测试和课程展示，不应承诺长期在线或对局持久化。玩家遇到服务刚唤醒时可能需要等待约一分钟，再重新打开页面。

## 运行约定

1. 发布者不得在已知有对局进行时部署新代码。
2. 正式约战前先访问 `/api/health`，确认服务已经唤醒。
3. 房间失效后重新创建，不尝试复用旧房间码或旧重连链接。
4. 不在聊天、截图或日志中公开私密重连凭证。
5. 免费服务达到额度或可靠性不足时，下一步优先升级常驻实例；需要恢复对局时再设计数据库持久化。

## 后续生产化门槛

若要把“公网测试版”提升为可持续上线版本，至少需要：持久化房间状态、实例重启恢复、服务端限流与容量监控、公开隐私说明，以及真实公网并发和异常恢复测试。这些不属于本子版本，不能用自动测试通过来替代。
