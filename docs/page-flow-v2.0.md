## v1.6 人机流程补充

- P01 创建区提供“2 人对战”“3 人自由战”“人机 1v1”三个互斥选项。
- 选择人机后，服务器创建 `bot_duel` 双人房，机器人自动占据第二席位；该房间不接受 `room:join`。
- 人机房直接进入 P03，机器人已完成随机合法部署并准备；真人仍可手动或随机部署。
- P04 真人每轮点击掷骰后，机器人自动提交；同点则等待真人下一轮重新点击。
- P05 机器人回合显示其短暂思考状态，客户端全部操作锁定；机器人由服务器提交并使用原权威结算器。
- 机器人首回合同样强制使用当前地图档位的雷达，所有隐藏武器和震爆结果继续遵守原信息隔离。
- FINAL_SALVO 中机器人秘密选择可用鱼雷，不显示选择内容；所有应提交方完成后同时结算。
- 真人点击“再来一局”即视为发起申请，机器人自动确认并进入全新部署。
- 真人赛后离开时关闭人机房，不留下可被真人加入的机器人空房。

## v1.5 流程补充

- P01 创建区继续由房主选择 2 人或 3 人房，房间人数创建后不可修改。
- P02 根据 `maxPlayers` 渲染 2 或 3 个席位；三人房间在第三名玩家加入后进入 P03。
- P04 全员掷骰，唯一最高点获得先手；最高点并列则全员重掷。
- P05 三人局为每名敌方玩家分别维护一张独立敌方地图。选择 B 时只读取/写入 B 的攻击历史、隐藏武器标记、侦察区域与私人标记；选择 C 时同理。
- 一个三人正常回合仍通过 `requiredTargetPlayerIds` 与 `remainingTargetPlayerIds` 表示本次同步防守方集合，但 `actionCount` 在合法回合结束时只增加 1，`completedTargetPlayerIds` 一次写入全部本次防守方。
- 所有行动都采用同一同步流程；直升机不再是例外。行动类型、来源、坐标或范围只选择一次，两张敌方地图同步预览。
- 每名玩家首个正常回合强制使用雷达扫描；三人局从任一敌方地图选择区域起点后，同一范围同时扫描两名敌人并结束回合。
- 若行动开始前已有敌人出局、投降或断线超时，则同步集合只保留仍在局敌人；只剩一人时自然退化为单目标行动。
- 三人回合只有一个 90 秒截止时间和一次提交机会；超时直接结束该玩家本回合。
- 三人手动终局鱼雷中，每名玩家每轮仍只秘密选择一枚己方未引爆鱼雷，但该鱼雷以同名坐标同时攻击其他所有仍在局玩家；不再只攻击座位顺序中的下一人。
- 行动消息按行动方、各防守方和公共记录分级；所有同步行动对每张敌方地图分别生成安全结果，防守方之间互不泄露。

## 1. 本阶段目标

本设计把已经冻结的游戏规则转换为后续可以直接实现和测试的产品流程，重点解决四件事：

1. 玩家在每个阶段能看到什么、能操作什么；
2. 房间、部署、掷骰、回合、暂停和结算如何流转；
3. 己方信息、敌方公开信息和敌方秘密信息如何隔离；
4. 超时、断线、自动跳过和终局手动鱼雷如何进入同一套状态模型。

本阶段确认后才建立项目。后续实现不得绕过本文定义的页面边界和状态流转。

## 2. 设计原则

1. **低成本实现**：首版采用单页应用，不引入前端框架和前端路由库。
2. **服务器权威**：客户端只显示服务器状态并提交意图；倒计时、命中、伤害、弹药和胜负均不由客户端决定。
3. **信息最小化**：对局结束前，服务器不给客户端发送任何不应看到的敌方部署信息。
4. **先清楚后华丽**：动画只辅助表达，不能阻塞或改变真实结算。
5. **桌面优先、手机可用**：桌面同时显示己方地图与敌方地图；三人局可同时展开两张敌方地图，手机通过标签在各地图之间切换。
6. **操作可撤销到提交前**：部署和目标选择可取消；行动一旦被服务器接受便不可撤销。
7. **不用颜色作为唯一提示**：命中、未命中、不可用、倒计时等状态同时使用图形或文字。

## 3. 应用入口与页面组织

### 3.1 地址设计

首版只使用一个 HTML 入口：

- 首页地址：/
- 房间地址：/?room=ABC123

创建或加入房间后，浏览器地址更新为带房间码的形式。刷新页面时，客户端使用本机保存的私密重连凭证向服务器恢复座位。没有有效凭证时，只能作为新玩家申请加入，不能恢复他人座位。

选择查询参数而不使用复杂路由，是为了减少部署配置和刷新页面时的服务器处理。

## 4. 服务器状态模型

为避免把“对局阶段”“回合处理”和“连接状态”混成一个巨大的状态枚举，服务器状态分为三条互相配合的状态轴。

### 4.1 房间阶段 roomPhase

| 状态 | 含义 | 允许的主要操作 | 下一状态 |
| --- | --- | --- | --- |
| WAITING | 房间尚未达到 `maxPlayers` | 加入、复制房间码、离开 | DEPLOYING 或 CLOSED |
| DEPLOYING | 房间内所有玩家部署舰队 | 放置、旋转、撤回、随机部署、准备 | ROLLING 或 CLOSED |
| ROLLING | 部署锁定，等待所有玩家主动掷骰并由服务器决定先手 | 每名玩家每轮主动提交一次掷骰意图；先手确定后展示结果 | PLAYING |
| PLAYING | 正式对战进行中 | 当前玩家完成一次合法行动；三人局同一意图同步作用全部仍在局敌人；仍在局玩家可投降 | FINAL_SALVO、FINISHED 或 CLOSED |
| FINAL_SALVO | 所有仍在局玩家手动逐枚引爆剩余鱼雷 | 每轮秘密选择 1 枚；所有仍在局玩家提交后同时结算 | FINISHED |
| FINISHED | 本局已结束 | 复盘、申请再来一局、离开 | DEPLOYING、WAITING 或 CLOSED |
| CLOSED | 房间已关闭或对局已取消 | 返回首页 | 无 |

### 4.2 回合阶段 turnPhase

turnPhase 只在 roomPhase 为 PLAYING 时存在。

| 状态 | 含义 | 是否运行 90 秒计时 |
| --- | --- | ---: |
| ACTIVE | 当前玩家可以选择并提交行动 | 是 |
| RESOLVING | 服务器正在验证并原子结算行动 | 否 |
| AUTO_SKIPPING | 当前玩家没有合法行动，服务器自动跳过 | 否 |

回合计数只在一名玩家取得新的正常回合并进入 ACTIVE 时增加一次。双人局与三人局都只允许一次行动提交；三人局在该行动中一次性完成全部同步防守方，结算后直接切换至下一名仍在局玩家。行动超时仍属于一个实际玩家回合；无合法行动自动跳过没有给予行动机会，不计入回合数，但必须写入行动记录。

### 4.3 连接状态 connectionPhase

| 状态 | 含义 | 页面表现 |
| --- | --- | --- |
| CONNECTED | 当前需要在线的玩家均在线 | 正常显示当前页面 |
| PAUSED_ONE_OFFLINE | 一名玩家离线 | 阻塞操作，显示离线方和 120 秒服务器倒计时 |
| PAUSED_BOTH_OFFLINE | 所有当前需要在线的玩家均离线（沿用历史枚举名） | 服务器保留状态；任一玩家重连后重新同步 |

连接状态不会自行改变 roomPhase。只有服务器根据 120 秒规则作出关闭房间、取消对局或判负后，roomPhase 才进入 CLOSED 或 FINISHED。

### 4.4 状态转换约束

1. 所有阶段转换只能由服务器产生，客户端不能自行跳页。
2. 客户端收到完整状态快照后，根据 roomPhase 选择 P02～P06。
3. RESOLVING 期间按钮全部锁定，避免重复提交；相同行动编号即使重复到达服务器也只结算一次。
4. 骰子、范围攻击和每轮终局鱼雷均由服务器权威结算，再把安全结果发给客户端。
5. 服务器发送绝对截止时间，客户端只负责显示剩余时间；刷新或后台挂起后重新按服务器时间校正。
6. 每次状态消息包含单调递增的状态版本号；客户端忽略比当前版本旧的消息。

### 4.5 胜负与终局检查顺序

服务器在一个原子结算点只产生一次权威状态转换，并按 `rule-v1.8` 处理：

1. 已接受的攻击行动先完整结算伤害与自损。双人局中任一航空母舰沉没后按规则结束；三人局中航空母舰沉没的玩家出局，若只剩一名未出局玩家则进入 FINISHED，否则跳过出局玩家继续回合。
2. 海盗船特殊规则在三人局分别作用于每名防守方，但海盗船自损与己方航空母舰联动伤害只结算一次；三人局仍以结算后的未出局玩家集合决定是否立即结束。
3. 投降、连续三次实际行动超时和断线超时均按“该玩家落败/出局”处理；三人局未只剩一人时继续对局。
4. 三人局一次行动对全部仍在局敌方玩家结算完成后，切换到下一名仍在局玩家；不会回到当前玩家执行第二项行动。
5. 每次合法行动或出局处理后，若所有仍在局玩家均无攻击手段，则进入 FINAL_SALVO。
6. FINAL_SALVO 中所有仍在局玩家秘密提交；双人攻击唯一对手，三人每枚已选鱼雷同时攻击其他全部仍在局玩家的同名坐标；全部剩余鱼雷处理完后比较航空母舰生命值。
7. 客户端动画不得改变上述顺序，也不得在服务器尚未给出最终状态前自行判胜负。

## 5. P01 进入游戏页

### 5.1 页面结构

- 游戏名称与一句话说明；
- 昵称输入框，长度提示为 1～12 个字符；
- 创建模式下的地图档位选择：10×10、12×12、15×15，默认 12×12；
- “创建房间”按钮；
- 6 位房间码输入框；
- “加入房间”按钮；
- “游戏规则”入口；
- 若检测到本机尚有效的重连凭证，顶部显示“恢复上次对局”卡片。

### 5.2 交互规则

1. 昵称去除首尾空白后验证，不能为空且不能超过 12 个字符。
2. 房间码输入统一转为大写，只接受 6 位服务器允许字符。
3. 点击按钮后进入提交中状态，防止连续创建或加入。
4. 创建成功后写入房间码和私密重连凭证，并进入 P02。
5. 加入成功后由服务器阶段决定进入 P02 或 P03。
6. 房间不存在、已满或对局已开始时，停留在本页并显示明确原因。
7. 房间码不显示为密码，也不能代替重连凭证。
8. 地图档位只随创建房间请求提交；加入房间、恢复对局和复制邀请链接均以服务器房间配置为准。

## 6. P02 房间等待页

### 6.1 页面结构

- 房间码和“复制房间码”按钮；
- 2～3 个玩家席位卡：昵称、在线状态、是否已进入；
- “等待其他玩家”状态；
- “离开房间”按钮；
- 精简规则入口。

等待阶段不显示部署地图，不提前启动 180 秒倒计时。房间达到创建时固定的 `maxPlayers`（2 或 3）后，服务器进入 DEPLOYING，所有席位同时切换到 P03。

### 6.2 断线

对局开始前有玩家断线时保留座位 120 秒。断线期间 O02 覆盖当前页；超时未返回时服务器关闭房间，在线方进入 O05。

### 7.2 舰队清单

清单固定展示八个作战单位，并按地图档位展示 2、3 或 5 个诱饵鱼雷。每项显示：

2. 已放置对象可拖到新位置；非法落点恢复原位置。
3. 已完成的航空母舰可整体拖动或旋转；若新位置非法则恢复原状。
4. 点击已放置对象后可“撤回”；航空母舰编辑时也可撤销最后一个格。
5. “随机部署”生成整套合法部署；若当前已有手动部署，先二次确认是否覆盖。
6. “清空部署”需二次确认。
7. 客户端即时预览只用于便利；点击“准备”时服务器再次完整验证。

### 7.4 准备按钮状态

- 本方部署不完整或非法：准备按钮禁用，并列出缺失项；
- 本方部署完整合法且尚未准备：准备按钮可用；
- 本方已准备且其他玩家均尚未准备：显示“取消准备”，可用；
- 只要已有其他玩家准备：本方已准备后不能再取消，避免多人房间出现交叉撤回；
- 所有 `maxPlayers` 席位都准备后：服务器立即锁定部署并进入 ROLLING。

本方准备后地图进入只读状态。180 秒结束时，服务器为尚未准备的玩家随机补全合法部署并自动准备；所有玩家看到同一权威阶段转换。

## 8. P04 掷骰决定先手页

页面同时显示全部玩家昵称、骰子、当前轮次与投掷状态。

流程如下：

1. 所有玩家进入 ROLLING 后，服务器等待每名玩家主动点击“掷骰子”；
2. 每名玩家每轮只能提交一次掷骰请求，骰子点数仍完全由服务器随机生成；
3. 玩家提交后立即看到自己的服务器点数，并等待该轮其他玩家完成投掷；
4. 全部玩家完成该轮投掷后，唯一最高点获得先手；
5. 若最高点并列，则该轮记录进入历史，所有玩家进入下一轮并再次主动点击“掷骰子”；
6. 分出先手后显示全部最终点数与“某玩家获得第一回合”；
7. 先手结果在原阶段展示时间基础上额外停留 3 秒，再由服务器切换到 P05。

客户端按钮只负责表达“我要掷骰”的交互意图，不生成随机数，也不能指定或修改点数。刷新或重连后继续使用服务器保存的当前轮次、已投点数与最终结果，不重复投掷已完成的本轮操作。

## 9. P05 对战页

### 9.1 桌面布局

    ┌────── 房间码 | 全部玩家昵称与在线状态 | 当前回合 | 90 秒 ──────┐
    │                                                               │
    │  己方地图 N×N      当前选中敌方地图 N×N      行动与单位状态面板 │
    │                                                               │
    ├───────────────────────────────────────────────────────────────┤
    │  公开行动记录                         规则   投降               │
    └───────────────────────────────────────────────────────────────┘

三人局桌面可同时展开己方与两张敌方地图。为减少横向滚动，三人战斗地图的 `.ocean-board` 显示比例为 0.85；任意模式的 15×15 地图显示比例为 0.9；三人 15×15 使用 0.765。坐标轴和格子必须作为同一个网格整体缩放，不能只缩放格子造成错位。

### 9.2 手机布局

- 顶部固定显示当前回合和倒计时；
- 使用“敌方地图 / 己方地图”标签切换地图；三人局敌方地图内再切换目标玩家；
- 默认进入敌方地图，受到新攻击时在己方地图标签显示提醒点；
- 行动面板放在底部抽屉，可展开或收起；
- 行动记录为可折叠区域；
- 不依赖鼠标悬停，所有预览都支持点击。

### 9.3 顶部对局状态

顶部必须始终显示：

- 当前行动玩家；
- 本方是“你的回合”或“等待其他玩家”；
- 服务器同步的剩余秒数；
- 全部玩家在线状态；
- 本方连续行动超时次数；
- 当前总回合数。

倒计时在 30 秒时进入警告样式，10 秒时进入紧急样式，但不播放连续刺耳声音。

### 9.4 己方地图

己方地图显示：

- 全部己方作战单位及正式名称或图形；
- 当前地图档位对应数量的诱饵鱼雷及其有效或已摧毁状态；
- 各单位格的未受击、已受击、残骸和本回合瘫痪状态；
- 当前行动来源对应的单位轮廓；
- 驱逐舰行动被选中时，在己方图上突出其中心格或两个中间格。

地图旁的单位状态卡显示本方生命值、剩余弹药、存活/沉没、瘫痪状态和行动可用原因。被震爆弹影响的单位显示“瘫痪：本回合不能行动”；敌方永远看不到这些状态卡。

### 9.5 三人敌方地图与同步目标

三人局中，另外两名玩家始终拥有两份互相独立的敌方地图状态。界面可以一次只展示当前选中的一张地图，但切换显示不得合并底层记录。

当前玩家取得回合时，页面从服务器 `turn` 状态读取：

- `requiredTargetPlayerIds`：本回合建立时的同步防守方集合；
- `completedTargetPlayerIds`：行动结算后一次写入的全部防守方；
- `remainingTargetPlayerIds`：行动提交前仍在局、将同时受到作用的防守方；
- `actionCount`：本回合已完成的服务器行动数，只能由 0 变为 1。

普通三人回合的界面流程：

1. 两张敌方地图均显示“同步目标”，玩家可以切换查看或从任一张地图选择坐标；
2. 选择行动后，两张敌方地图同时显示同一目标或范围预览；
3. 确认层列出全部同步防守方，并明确“资源与行动方自损只结算一次”；
4. 提交后服务器一次记录全部 `defenderIds`，分别写入每名敌人的独立地图；
5. 结算完成后当前玩家回合结束，不提供第二项操作。

直升机扫射、雷达、探测、震爆和全部单格行动均使用上述统一流程。

### 9.6 敌方地图基础状态与潜射标记

每个敌方地图格只有三种互斥基础状态：

| 基础状态 | 视觉内容 | 是否可作为单格攻击目标 |
| --- | --- | ---: |
| 未知 | 海面底色 | 是，但仍需满足具体攻击范围 |
| 命中 | 红色命中图形和文字替代提示 | 是，但仍需满足具体行动规则；驱逐舰禁止再次选择己方任一驱逐舰已经攻击过的坐标 |
| 未命中 | 浅色水花或叉号 | 是，但仍需满足具体行动规则；驱逐舰禁止再次选择己方任一驱逐舰已经攻击过的坐标 |

攻击方敌方地图永远不显示沉没、舰种、剩余生命值、完整轮廓或诱饵身份。

“导弹已发射”不是第四种基础状态，而是覆盖在“未知”基础状态上的独立潜射标记：

- 潜射导弹发射后，目标格显示“导弹已发射”，不显示命中或未命中；
- 该标记不会限制后续选择；命中、未命中和潜射标记格均可按具体行动规则再次作为单格目标，驱逐舰仍受行动方共享的已攻击坐标限制；
- 范围攻击不会因为该标记而跳过该格；
- 若后续其他行动公开得出“命中”或“未命中”，该格转为相应基础状态；潜射历史仍保留在行动记录中。

### 9.7 情报覆盖层

探测弹和震爆弹不会改变基础状态，两者分别形成独立的区域记录：

- 探测弹记录中心格、3×3 作用区域、布尔探测结果和发生回合；
- 震爆弹记录中心格、当前档位作用区域和发生回合，不记录成功或失败；
- 地图默认以淡色边框显示最近一次探测或震爆区域；
- 点击行动记录可重新高亮对应的探测、雷达或震爆区域；
- 多个区域重叠时不合并结果，也不覆盖更早记录；
- 情报区域中的格仍可正常成为攻击目标，只要基础状态为未知且符合行动范围。

### 9.8 五类本机私人标记

1. 每张敌方地图上方固定显示五个标记工具：确定有、水面有、水面无、水下有、水下无；桌面仍支持 M 键切换标记模式。
2. 玩家点击一种工具后进入标记模式；左键未知格直接写入所选类型，再次选择其他类型可覆盖，不提交游戏行动。
3. 右键已有私人标记的格立即删除该标记；右键未标记格、公开命中/未命中格或其他自动标记不执行删除。
4. 普通目标选择模式和标记模式互斥，避免误操作。
5. 某格收到命中或未命中公开结果后，私人标记不再绘制，自动结果优先；玩家不能修改服务器公开状态。
6. 私人标记只保存在本机浏览器，并按房间、本机玩家和敌方玩家隔离；随同一设备重连恢复，不发送给服务器或对手。

### 9.9 单元格视觉优先级

同一格出现多个显示状态时，从高到低按以下顺序绘制：

1. 当前目标和即将作用的范围预览；
2. 命中或未命中基础状态；
3. “导弹已发射”潜射标记；
4. 五类本机私人标记；
5. 当前选中的探测或震爆情报边框；
6. 海面底色。

该优先级只影响显示，不改变服务器状态。

## 10. 行动选择与提交

### 10.1 客户端交互状态

当前玩家的操作按以下步骤流转：

    未选择行动
         ↓ 选择可用行动
    正在选择目标
         ↓ 选择合法格、行或列
    等待确认
       ├─ 取消 → 正在选择目标
       └─ 确认 → 正在提交
                       ↓
                  等待服务器结算
                    ├─ 拒绝 → 返回选择并显示原因
                    └─ 接受 → 展示结果
                                  └─ 完成本回合 → 切换下一名仍在局玩家

在“等待确认”之前不消耗行动或弹药。服务器接受行动后，即使客户端断线，结算也必须完成。

### 10.2 行动卡状态

每个行动卡只能是以下一种状态：

- 可用：本方回合且满足来源、弹药、解锁和合法目标条件；
- 等待回合：行动本身可用，但当前不是本方回合；
- 已沉没：行动来源已沉没；
- 瘫痪：行动来源本回合受震爆影响，并显示“该单位本回合不能行动”；
- 弹药耗尽：有限资源为 0；
- 尚未解锁：只用于直升机扫射，并显示“己方两艘驱逐舰均沉没后解锁”；
- 无合法目标：仅用于两艘驱逐舰的范围内坐标均已被驱逐舰尝试过，或所选范围本身无有效坐标；
- 提交锁定：服务器正在处理上一请求。

禁用状态必须显示文字原因，不能只变灰。

### 10.3 各行动的目标界面

| 行动 | 选择方式 | 合法目标预览 | 确认信息 |
| --- | --- | --- | --- |

| 海盗船攻击 | 选择 1 格 | 全图任意格 | 命中单位时目标 −2、海盗船 −1；海盗船实际受伤时己方航母 −0.5 |

| 探测弹 | 选择中心格 | 预览完整 3×3 | 行动名称、中心格、提交后弹药耗尽 |
| 航空母舰雷达扫描 | 选择区域左上角 | 预览当前档位完整 3×3、4×4 或 5×5；三人首回合同一区域同步预览两名敌人 | 行动名称、全部同步防守方、扫描区域；只向行动方按防守方分别返回是否发现布局 |
| 直升机扫射 | 先选“行”或“列”，再选坐标 | 高亮完整 N 格；三人局以同一行/列同时预览全部仍在局敌方地图 | 行动名称、整行或整列；只命中水面单位，对每名敌方航空母舰本次总伤害最多为 2 |

选择驱逐舰行动时，己方地图同时显示范围中心；敌方地图只显示可选格，不绘制任何敌方秘密信息。

海盗船确认层说明：成功命中任一作战单位时目标 −2、海盗船 −1；命中诱饵时诱饵被摧毁、海盗船受爆炸伤害 1；海盗船每次实际受伤使己方航空母舰联动损失 0.5；未命中无伤害。

摩托艇确认层须说明：只有命中航空母舰时目标受到 1 点伤害；命中其他水面单位只返回命中而不伤害目标；命中水面单位或诱饵鱼雷后摩托艇自身沉没；潜水艇和核潜艇不属于可命中对象。

直升机扫射选择当前地图完整 N 格行或列。此前命中、未命中或带有潜射标记的格都仍按本次行动正常进入扫射结算；已具有伤害历史的单位格不会重复造成伤害。扫射只命中水面单位，不命中水下单位或诱饵鱼雷；同一次扫射对航空母舰的总伤害上限为 2，但覆盖到的所有未结算航空母舰单位格仍分别显示命中。

### 10.4 行动结果反馈

1. 除潜射导弹和核弹外，单格攻击只向攻击方显示“命中”或“未命中”，不显示敌方舰种、伤害或沉没；三人局按敌方玩家分别显示合法的命中结论。
2. 潜射导弹结算后，发射方只看到目标格新增“导弹已发射”标记，不收到命中、未命中、目标类型、伤害或沉没信息。
3. 防守方始终看到“行动方使用潜射导弹攻击了某格”；若命中，防守方正常看到己方单位受伤、沉没或诱饵鱼雷被摧毁；若未命中，不再显示任何附加结果。
4. 潜射标记不把格子变为已结算格。该格可被再次单格攻击，范围攻击也正常处理；若同一单位格此前已被潜射导弹实际命中，服务器仍执行后续行动反馈，但不得从该单位格重复扣除生命值。
5. 直升机扫射逐格更新命中或未命中；三人局同一行/列同时在所有仍在局敌方地图上分别结算并写入各自地图记录。
6. 探测弹只显示“探测到水下信号”或“未探测到水下信号”；三人局按敌方玩家分别返回两份私人结果。
7. 震爆弹施加方只看到行动已使用、中心格和当前档位作用区域，不显示“震爆成功”或“震爆失败”，也不显示受影响单位的数量、类型或坐标。
8. 震爆弹防守方在己方地图和单位状态卡中看到实际被瘫痪的潜水艇或核潜艇；全部水面单位和诱饵鱼雷不受影响。
9. 防守方在己方状态卡上看到自己实际生命值变化、沉没和瘫痪状态。
10. 海盗船行动造成的海盗船自身伤害和己方航空母舰伤害必须向该玩家正常显示。服务器不直接公开敌方目标类型，但玩家可以依据己方实际状态变化自行推断。
11. 动画总时长应短，玩家可关闭动画；跳过动画不跳过服务器结算。

### 10.5 三人回合操作顺序

当 A 的回合开始且 B、C 均仍在局时：

1. A 选择一项合法行动；B、C 两张敌方地图同时进入该行动的合法目标预览状态；
2. A 可以从任一张敌方地图选择目标，但选择的坐标、区域、行或列同步显示在两张地图；
3. O03 确认层列出 B、C，并说明弹药、使用次数和行动方自损只结算一次；
4. 服务器提交一次行动资源，再分别对 B、C 结算目标效果；每名防守方只收到自己的消息；
5. 一次原子结算完成后 A 的回合结束，切换到下一名仍在局玩家。

雷达、直升机、单格攻击、探测弹和震爆弹均使用这一个流程，不再存在“第二项行动”或“直升机例外”。若回合开始前只剩一名敌人，确认层只显示该敌人并按双人单目标交互执行。

## 11. 公开记录与私密通知

### 11.1 所有玩家可见的公开行动记录

每条记录包含：

- 回合序号；
- 行动玩家昵称；
- 防守玩家昵称；三人所有行动均列出全部同步防守玩家；
- 正式行动名称；
- 公开目标：单格、当前档位区域中心格、完整一行或完整一列；
- 按规则允许公开的结果；
- 行动超时、无合法行动自动跳过、投降和断线结果。

公开记录不得包含敌方舰种、敌方剩余生命值、诱饵身份或未公开坐标。三人公共记录也不得包含任一防守方的命中/未命中、探测或雷达结果，防止结果在防守方之间泄露。

潜射导弹记录采用固定句式“玩家使用潜射导弹攻击了 B3”；记录中不添加命中、未命中、目标类型或伤害字段。发射方敌方地图同时在该目标格保留“导弹已发射”标记。

震爆弹记录采用固定句式“玩家以 E5 为中心使用震爆弹”；可以重放当前档位区域，但记录中不添加成功、失败、受影响单位数量、类型或坐标。

### 11.2 仅本方可见的通知

- 己方单位实际受到的伤害；
- 己方单位沉没；
- 己方诱饵鱼雷被摧毁；
- 己方单位当前是否瘫痪及瘫痪解除；
- 己方剩余弹药和行动可用状态；
- 非法请求的具体拒绝原因。

对局结束进入 FINISHED 后，房间内所有参战玩家获得完整复盘记录，不再执行上述隐藏。

## 13. 自动流程和异常流程

### 13.1 行动超时

1. 每名玩家取得正常回合时服务器只创建一个 90 秒截止时间；双人局与三人局均在该窗口内提交一次行动。
2. 截止时间到达时若尚未提交行动，服务器立即结束该玩家回合；不会生成或补做任何行动。
3. 公开记录写入“行动超时”，该玩家连续超时次数加 1。
4. 达到 3 次时，该玩家在双人局落败、在三人局出局；若只剩一名仍在局玩家则进入 FINISHED。
5. 完成一次合法行动，或因已无任何合法行动而正常结束回合，才将该玩家连续超时次数清零。
6. 未达到 3 次时切换到下一名仍在局玩家。

客户端倒计时到 0 只能显示等待状态，最终是否超时以服务器消息为准。

### 13.2 震爆瘫痪回合

防守方下一个正常回合开始时，服务器应用待生效的单位级瘫痪：

1. 当前档位震爆区域曾覆盖任意单位格的存活潜水艇或核潜艇，整艘水下单位显示“瘫痪：本回合不能行动”；水面单位和诱饵鱼雷不受影响；
2. 瘫痪单位对应的行动卡禁用，未瘫痪单位仍按通常条件判断是否可用；
3. 若至少存在一个由未瘫痪单位发动的合法行动，进入 ACTIVE 并正常启动 90 秒计时；
4. 双人局与三人局均在该玩家唯一一次行动完整结算、整个回合结束后解除瘫痪；
5. 若本回合不存在任何合法行动，进入 AUTO_SKIPPING，不启动计时、不增加连续超时次数；自动跳过后解除全部瘫痪；
6. 公开记录只写“当前玩家没有可用行动，本回合自动跳过”，不得列出瘫痪单位或直接显示震爆是否成功。

### 13.3 无合法行动自动跳过

若当前玩家没有任何合法行动，但仍有其他在局玩家具备合法行动：

1. 进入 AUTO_SKIPPING；
2. 显示“当前没有合法行动，回合自动跳过”；
3. 不启动 90 秒计时，不增加连续超时次数；
4. 切换到下一名仍在局玩家。

若所有仍在局玩家都没有攻击手段，优先进入 FINAL_SALVO，而不是让玩家无限自动跳过。服务器必须防止自动跳过形成死循环。

瘫痪属于只持续一个回合的临时状态，不得据此判定某方永久失去攻击手段，也不得仅因当前全部行动来源瘫痪而提前进入 FINAL_SALVO。

### 13.4 终局手动鱼雷引爆

进入 FINAL_SALVO 后：

1. 普通行动面板锁定，己方地图中的未触发鱼雷变为可选按钮；
2. 每轮每名仍在局玩家秘密提交一枚；界面只显示各玩家“已提交/等待提交”，不泄露其他玩家所选坐标；
3. 所有仍在局玩家都提交后服务器同时结算本轮并移除已引爆鱼雷；双人每枚鱼雷攻击唯一对手，三人每枚鱼雷同时攻击另外所有仍在局玩家的同名坐标；无鱼雷玩家自动跳过；
4. 若仍有可用鱼雷，增加轮次并继续选择；全部耗尽后展示所有仍在局玩家航空母舰最终生命值；
5. 按服务器结果进入 FINISHED。刷新只恢复服务器确认的当前轮次，不重复结算。

刷新页面或跳过动画时直接显示已完成的齐射结果，不重复发射。

### 13.5 非法行动与重复提交

- 非法行动不结束回合、不消耗弹药，客户端显示服务器具体原因；
- 若是状态已过期，客户端立即请求最新完整快照；
- 网络重试必须复用同一个行动编号；
- 服务器返回该编号原有结果，而不是再次结算；
- 提交期间客户端不能再选择第二个行动。

### 13.6 投降

投降按钮在 roomPhase 为 PLAYING 时显示。在线玩家即使正在等待断线方重连，也可以在 O02 中选择“投降并离开”。点击后弹出二次确认：双人局说明“投降后本局立即失败”，三人局说明“投降后你将立即出局”；均不可撤销。

服务器按顺序处理已经接受的事件：若一个攻击行动已经进入 RESOLVING，先完成该行动；若它已经按更高优先级摧毁航空母舰，则按该攻击行动的胜负结算，否则再接受投降并进入 FINISHED。

### 13.7 海盗船特殊胜负

海盗船攻击必须在一次原子结算中同时更新目标、海盗船和海盗船受伤触发的己方航空母舰联动伤害，再决定胜负：

- 敌方航空母舰沉没时，海盗船一方获胜；
- 双方航空母舰同时沉没时，仍判海盗船一方获胜；
- 只有己方航空母舰沉没时，海盗船一方失败。

## 14. 断线与重连流程

### 14.1 通用显示

一名玩家断线后，在线玩家看到 O02：

- 哪位玩家已断线；
- 服务器剩余等待时间；
- “正在等待重连，当前操作已暂停”；
- 对局开始前显示“离开房间”；对局开始后显示“投降并离开”，不使用含义模糊的“返回首页”。

断线玩家重连时先看到“正在恢复对局”，收到完整安全快照后再显示当前页面。

### 14.2 对局开始前

WAITING、DEPLOYING 和 ROLLING 均按“对局开始前”处理：

- 断线方座位保留 120 秒；
- 暂停当前页面的可操作内容；
- DEPLOYING 的 180 秒倒计时暂停，重连后按服务器剩余时间继续；
- 断线期间不进入 ROLLING 或 PLAYING；
- 超时未返回时进入 CLOSED，不判胜负。

### 14.3 对局开始后

PLAYING 和 FINAL_SALVO 按“对局开始后”处理：

- 任一仍在局玩家断线立即暂停；
- 当前行动倒计时冻结，重连后按服务器保存的剩余时间继续；
- 120 秒内重连则从服务器确认状态继续；
- 某名断线玩家超时后，双人局该玩家判负；三人局该玩家出局，若仍有至少两名玩家在局则继续，否则进入 FINISHED；
- 所有仍在局玩家均离线且均未按各自期限返回时，进入 CLOSED，并标记“对局取消，不判胜负”。

断线发生在行动已经被服务器接受之后，该行动必须先完成原子结算；重连后从结算后的状态继续，不能回滚或重复行动。

## 15. P06 对局结算页

### 15.1 结果摘要

- 胜利、失败或平局；
- 唯一胜负原因；
- 对局总回合数；
- 对局持续时间；
- 所有参战玩家最终航空母舰生命值；
- “再来一局”和“离开房间”按钮。

若由海盗船特殊规则结束对局，胜负原因必须明确显示“海盗船攻击使敌方航空母舰沉没”或“海盗船攻击仅使己方航空母舰沉没”，双方同时沉没时注明“按海盗船特殊规则，海盗船一方获胜”。

### 15.2 完整复盘

结算后按所有参战玩家提供地图标签，公开：

- 所有参战玩家完整部署和所有对象真实身份；
- 最终生命值；
- 剩余弹药；
- 所有单位格受击状态和残骸；
- 完整行动记录；
- 终局每轮鱼雷选择、目标与同时伤害（若发生）。

公开记录与复盘信息分栏展示，避免把对局中可见信息和结算后揭示信息混为一体。

### 15.3 再来一局

| 本方状态 | 其他玩家状态 | 页面反馈 |
| --- | --- | --- |
| 未申请 | 任意 | “再来一局”可用，并逐名显示其他玩家申请状态 |
| 已申请 | 尚有人未申请 | “你已申请”，逐名显示“已申请/等待确认”，并允许取消 |
| 已申请 | 所有保留席位均已申请且在线 | 服务器进入 DEPLOYING，清空上局部署和资源 |
| 任一玩家离开 | 其余玩家留下 | 保留所有剩余席位并进入 WAITING，可继续邀请玩家补满房间 |

所有保留席位的玩家确认再来一局且全部在线后必须重新部署、恢复初始资源并重新掷骰；只保留昵称、房间和玩家座位。

## 16. 视觉与可用性基线

### 16.1 视觉方向

- 风格：深海战术界面；
- 主背景：深海军蓝；
- 可交互强调：青蓝；
- 命中：红色加爆点图形；
- 未命中：浅灰蓝加水花或叉号；
- 导弹已发射：黄色或橙色导弹图标，并配同名文字提示；
- 瘫痪：仅在己方单位上使用紫色电弧或禁用图标，并配“本回合不能行动”文字；
- 警告：橙色；
- 字体：优先使用系统中文字体，不下载大型字体文件；
- 舰艇和状态图形优先使用 CSS、简单 SVG 或轻量本地资源。

最终配色在写界面时可以微调，但状态含义不能改变。

### 16.2 可用性要求

1. 当前地图全部行列坐标始终可见：10×10 为 A～J/1～10，12×12 为 A～L/1～12，15×15 为 A～O/1～15。
2. 桌面端单格点击区域不小于 36×36 像素；手机端尽量不小于 32×32 像素。
3. 所有按钮有正常、悬停、聚焦、禁用和提交中状态。
4. 键盘可以聚焦地图格并确认选择；焦点边框清晰。
5. 重要弹窗初始焦点放在安全按钮，例如“取消”。
6. 页面刷新、窗口缩放和手机横竖屏切换不能改变游戏状态。
7. 低性能设备可关闭动画，且不影响任何功能。

## 17. 错误信息规范

错误信息必须说明原因和下一步，不使用单独的“失败”。

| 场景 | 推荐文本 |
| --- | --- |
| 房间不存在 | “未找到该房间，请检查 6 位房间码。” |
| 房间已满 | “该房间席位已满。” |
| 对局已开始 | “该房间的对局已经开始，不能加入。” |
| 部署不完整 | “还有以下对象未部署：……” |
| 部署非法 | “部署重叠或越界，请调整红色标记区域。” |
| 非本人回合 | “当前不是你的回合，已同步最新对局状态。” |
| 目标已结算 | “该格已有命中或未命中结果，请选择未知格。” |
| 超出攻击范围 | “目标不在该行动的攻击范围内。” |
| 弹药不足 | “该行动的弹药已经用完。” |
| 行动来源沉没 | “行动来源已经沉没，不能发动行动。” |
| 行动来源瘫痪 | “该单位本回合处于瘫痪状态，请选择其他可用单位。” |
| 网络中断 | “与服务器的连接已中断，正在尝试重连。” |
| 房间被关闭 | “玩家未在 120 秒内返回，房间已关闭。” |

只有“导弹已发射”标记而没有命中或未命中基础状态的格，不得触发“目标已结算”错误。

## 19. 已确认的五项设计决定

以下决定不修改游戏数值或胜负规则，但会影响后续实现。v1.4 继续采用：

1. 使用单页应用和 /?room=ABC123，不引入前端路由库；
2. 每个行动都采用“选择目标—确认提交”两步，减少误触；
3. 手机端以标签切换己方地图和敌方地图，不强行并排缩小；
4. 五类私人标记只保存在本机浏览器，不进入服务器战局数据；
5. 对局开始前有人断线时暂停部署倒计时并阻止进入掷骰或对战。
